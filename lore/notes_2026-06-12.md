## §196 — TASK_801 token front-end: the zero-init no-op that becomes load-bearing

**Believed before.** A token channel into the V3 encoder is a structural change to a
network whose canonical lineage (760 a1b1) we do not want to perturb. Any honest A/B needs
the OFF path to be *byte-identical* to the pre-token network, or the control arm is
contaminated from the first gradient.

**What happened.** TASK_801 ([[TASK_801]], commit `20f6966`) adds a per-timestep
candle-language token embedding into the encoder via a zero-init `token_proj` (the FiLM
trick — additive projection initialised to zero). Flag `use_token_frontend` defaults OFF.
Gate battery: E1/E2 byte-identical no-op when OFF, E3 grads reach `token_proj` in Stage B,
E4 streaming parity. All green. The zero-init means the token path contributes exactly
nothing until trained, so OFF ≡ canon is structural, not approximate.

**Lesson.** The FiLM zero-init is what makes the eventual `raw`-vs-`real_fe` comparison
clean: the difference between arms is *only* the token information, never an architecture
delta.

## §197 — TASK_801b Fork A: the forward-fill trap, solved by joining a no-fill timeline onto the grid

**Believed before.** Training windows just need their token ids looked up per timestep.

**What happened.** SegmentPool slots carry a `HistoricalMarket.cache_data` that is
**forward-filled** — ~476k fills per period. A naive per-row tokenisation would tokenise
filled (fake) bars and feed the trader a candle language describing flat-line artifacts.
The fix (TASK_801b Fork A, `8d64fc5`) is structural: build a **no-fill token timeline** and
**timestamp-join it onto the slot grid** — `annotate_asset` for real slots, `annotate_ohlcv`
for synthetic — so filled rows auto-mask (R2 solved by construction, not by a filter flag).
R3 join-audit B1–B4: B1 `annotate_asset` byte-identical across the refactor, B3 join ==
ground-truth, B4 synthetic cold-σ head curve sane. Then `6372758` wired the hot path
(flag-gated) and `85abe11` added a **pool-level per-asset timeline cache** keyed by
`(asset_id, vocab_sha)` — annotate-once-per-pool, collapsing the 64×N re-annotation to 64.
C1–C5: canon bit-identical OFF, train/serve parity.

**Lesson.** When the data substrate lies (forward-fill), don't patch the consumer — join a
truthful timeline onto the substrate's own grid and let the misalignment mask itself.

## §198 — The lag re-certification: re-deriving a "safe" bound on the real artifact overturns it

**Believed before.** Serving lag for L1 was **t−2** (LAG-1), established in `notes_2026-06-06.md`
§195 from a 256-merge in-process vocab fit, via an empirical-max+1 rule.

**What happened.** Re-certifying causal lag on the **frozen 512-merge canonical vocab**
(`runs/799_grammar/L1_RESULT_vocab.json`, cb 1376 — the vocab the trader actually serves)
**overturned LAG-1**. Measured lag histogram: `{0:960, 1:22, 2:11, 3:3, 4:3, 6:1}`, p99=2,
**max=6**. The old t−2 was a sample-size accident: the 256-merge fit simply never drew the
deep-recompute tail. Decision: set **`LANGUAGE_INPUT_LAG["L1"] = 3`** (p99-firm), and retire
the empirical-max+1 rule as what it always was — a sample statistic, not a bound. One
constant at `tools/candle_lang/token_window_slice.py:39`; `input_lag_for()` (line 44)
propagates it to every consumer. B2/C2/C3 re-run green at lag 3. Commits `0c283d8` (re-cert)
and `4a449df` (docstring sync).

**Reversal.** LAG-1 (t−2) → lag 3, derived on the frozen artifact rather than an in-process
fit. The prior "safe" value was unsafe because it was measured on a smaller vocab that hid
the tail (max 6 > the old assumption of 2).

**Lesson.** A constant chosen as "empirical max + 1" is only as safe as the sample that
produced the max. Re-derive bounds on the *canonical, frozen* artifact before you trust them.

## §200 — The control arm that couldn't fail (THE headline reversal)

**Believed before.** TASK_804's random-codebook null ([[TASK_804]]) — the placebo that the
whole branch-C verdict leans on — was built as a **frequency-matched id permutation π**
(TASK_804-B2, helper landed `99d4cf1`). The idea: relabel token ids under a permutation that
preserves the marginal frequency distribution, so the "null" arm sees statistically-matched-
but-meaningless tokens. A drug-shaped placebo.

**What happened.** B2's **own acceptance audit falsified it** before it could run. Two
findings, escalating in depth:

1. **Mechanically inert.** ~95% of L1 tokens are leaf ids with no vocab indirection, and BPE
   segmentation depends on merge **rank order** — so a permuted vocab cannot even change the
   encoding. π was, at the encoder, a no-op.
2. **The real problem — information-theoretically guaranteed to pass.** Relabeling ids with a
   *fresh embedding table* preserves the token **sequence**. The model simply relearns
   id→embedding. So the "null" arm carries the **identical token information** as the
   treatment arm, by construction. It is a placebo chemically identical to the drug. Had it
   run, it would have matched `real_fe` and we would have recorded "the tokens do nothing" —
   a fabricated null, indistinguishable from a true one in the scorecard.

It was caught **by its own acceptance battery**, before it could spuriously match `real_fe`
and poison the branch-C verdict.

**The fix (TASK_804-B2.5, `125100d`).** Replace π with a **cyclic-shift null**: roll each
asset's token timeline by a large per-asset offset *before* the join. This **decouples
token↔bar alignment** (so the tokens no longer describe the bar the trader is acting on)
while **preserving the marginal multiset** (same tokens, same frequencies, wrong place). A
true placebo. Measured token↔bar agreement under the shift: **0.0186 ≈ Σp² = 0.0198**
(chance-like — the shifted timeline agrees with the true one no better than random draw from
the marginal). Arm renamed `rand_fe` → `shift_fe`. π kept in-tree as the **archived
dead-end record** (`99d4cf1`), not deleted — the falsified design is itself the evidence.

**Reversal.** The control arm was redefined from "frequency-matched id permutation" (a
guaranteed pass) to "cyclic-shift alignment break" (a genuine placebo, agreement 0.0186 vs
chance 0.0198). Magnitude that matters: π's effective agreement with treatment was **1.0**
(identical sequence); shift_fe's is **~0.019**. The difference between a null that always
passes and a null that can actually fail.

**Lesson — the keeper.** A control arm has to be able to *fail*. A measurement-first culture's
job is to audit the placebo as hard as the drug — because a placebo that is guaranteed to
match treatment will manufacture a clean-looking null and end an entire research branch on a
lie. This one was caught by its own gate, before it could lie.

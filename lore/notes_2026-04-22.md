## 29. Research Agent Findings — Alternatives if 729c Fails

Full report: `research/729c_ceiling_alternatives.md` (~1100 words).

**Top 3 ranked alternatives** (priority order):

1. **Cross-sectional rank oracle** — Replace `greedy_lookahead_path(k=4)` 93%-HOLD mask with a per-asset ranking target (each of 64 assets gets a rank label every step). Gives informative gradient to all assets instead of 4. Strongest literature backing: arXiv:2012.07149 (Learning to Rank for Cross-Sectional Strategies). Cheapest reformulation — reuses entire current encoder.

2. **Remove `asset_identity_embed` + 1-asset → N-asset curriculum** — Identity embed (`trm_encoder_v2.py:68` and `trm_encoder_v3.py:129-133`) may act as a shortcut the model leans on instead of learning per-asset direction from content. Test: ablate identity embed and re-run. Curriculum progression adds robustness.

3. **IQN distributional value head + Bella adversarial regimes** — Widen value distribution. Stops critic collapsing bull/bear paths to near-zero. Cites Frontiers 2025 portfolio RL.

**Key theoretical insight**: The 0.5%-noise → HOLD collapse (Section 1 audit in notes_2026-04-19.md) is a **textbook case** of KL-regularized policy mode collapse (arXiv:2510.20817), NOT Poppy-specific. BC-regularized MCTS with sparse labels is known to collapse to the majority class.

**Channel gap flagged**: `env/jax_encoder.py::_compute_all_channels_temporal` produces 27 channels but has **no cross-sectional features** (rank-of-return across the 64 assets, beta-to-universe, idiosyncratic vol). This is the one obvious gap in the input space.

**Single cheapest diagnostic** (<1 hr, no GPU contention): Compute `MI(latent, per-asset sign)` vs `MI(latent, per-asset rank)` on the 728c checkpoint. If rank-MI is materially higher, commit to alternative #1 (rank oracle) — no retrain wasted.

Even with subagents, I still had to read the same files to verify their claims. Main-thread context wasn't really preserved; it was just interleaved with agent reports. For implementation work where I have the context, the "saves context" argument is weak.

## 48. TASK_734 bug post-mortem + corrected option matrix

**What happened (2026-04-23 ~11:04):**

TASK_734 α-v1 ran to completion (E0→E199, ~2 hours). All metrics identical to TASK_732: dir_acc 0.576, rank_sp 0.237, same 0.57 ceiling. The CSV and per-epoch log shows `flow=v8.79/s8.79` every single epoch — velocity_loss and state_loss numerically identical to 4 decimals start to finish.

**The math bug:**
```
pred_velocity    = dyn_out   - latent_t_sg          (by my wiring)
actual_velocity  = latent_t1 - latent_t_sg
velocity_loss    = mean((pred_velocity - actual_velocity)²)
                 = mean(((dyn_out - latent_t_sg) - (latent_t1 - latent_t_sg))²)
                 = mean((dyn_out - latent_t1)²)     ← identical to state_loss
```

When both velocities share a common reference state (in this case `latent_t_sg`), the reference cancels under subtraction and the velocity loss collapses identically to the state loss. **Single-step, teacher-forced, supervised flow matching = single-step MSE — always, not just in our code.** This is a mathematical identity, not a wiring bug. It explains why the existing `mcts_trader/jax_agent/flow_matching.py` module has zero call sites since January: whoever wrote TASK_041 likely discovered the same collapse and parked the module.

**Corollary — what single-step flow matching CAN'T do:** give a different gradient than MSE on dynamics. Period.

**What flow matching actually requires to differ from MSE:**
- **Multi-step autoregressive unroll**: `pred_k` uses `pred_{k-1}` as input (not `actual_{k-1}`). Velocity at step k = `pred_k - pred_{k-1}`; target velocity = `actual_k - actual_{k-1}`. Now the two velocities don't share a reference, so the subtraction doesn't collapse.
- **Dedicated velocity output head with a separate gradient path**: model outputs `(s_pred, v_pred)` as two INDEPENDENT heads, with v_pred NOT tied to `s_pred - s_t`. If `s_pred = s_t + v_pred` (derived), still collapses to MSE. Only if v_pred has truly independent parameters and is supervised alone does it differ.
- **Stochastic trajectory integration** (flow matching literature standard): model learns a velocity field between two distributions (e.g. noise and data), integrated over continuous t ∈ [0,1]. Not applicable to our deterministic supervised setup.

|---|---|---|---|---|---|
| 728c (V2, 27ch) | ~60% | ~0.57 | (no head) | ~1.61 | ~9 |

**policy_loss = 1.61 = log(5) ≈ 1.609.** Exactly the cross-entropy of a uniform 5-way per-asset distribution. The policy is outputting *uniform* 5-way distributions per asset, MCTS visit counts match that uniformity, so the CE against targets stays flat at log(5) from E0 to E200 across every single run.

**This is the ExIt loop closed on itself:**

1. `--value-weight 0.0` has been set on *every* Stage B run since 729c. The value head isn't trained.
2. Encoder is unfrozen (`--encoder-lr 3e-5`). Latent drifts as encoder fine-tunes.
3. Value predictions (from a Phase-1-trained, now-untouched value head) diverge from the drifting latent → value outputs are effectively random/stale.
4. MCTS backs up values to compute Q-values. Garbage values → garbage Q-values → uniform-ish visit distribution.
5. Policy target from MCTS = uniform. Policy output starts uniform (or close). Policy CE to MCTS visits = log(5). Gradient ≈ 0. Policy never moves.
6. Auxiliary heads (direction, rank, aux_price) DO train because they have direct supervised signal bypassing MCTS. But their gradient doesn't flow into the *policy head* — it flows into the latent. The latent improves, but the policy head sees those improvements through a channel that never produces a changed target.

**We have been training a policy head that has no usable training signal for 6 consecutive Stage B runs.** Aux heads move the latent, but the policy head's only target (MCTS visits) is stuck at uniform because the value head that drives MCTS is frozen-and-drifting.

**The fix is one flag: `--value-weight 1.0` (was 0.0).**

With value training on:
- Value head tracks the drifting latent.
- Value predictions become meaningful TD estimates.
- MCTS Q-values become meaningful (reward + γ·V at leaf + backup).
- MCTS visit distribution concentrates on high-Q actions (not uniform).
- Policy target = MCTS visits = concentrated distribution.
- Policy cross-entropy drops below log(5). Policy output concentrates. dir_acc moves.

Why wasn't value_weight=0.0 caught earlier? It was presumably an ablation to isolate policy/direction training. Over 700 tasks the setting became load-bearing — we kept it across runs and never noticed it was disabling MCTS. The aux-head loss drops gave false reassurance that "something is training."

**This supersedes the "oracle is validation not target" framing from §46.** The oracle isn't great, but the *real* problem is that ExIt can't run without value training. We're not even running ExIt; we're running supervised BC + aux heads, with MCTS producing a constant uniform target that contributes nothing.

**Risks of turning value_weight on:**
- value_loss is currently ~50 (huge). Enabling it with weight 1.0 would make value dominate total_loss by 5-10×. Start lower: weight=0.5 or 0.25, then tune.
- Phase 1 value head used PopArt normalization with different stats than current Stage B. Value might briefly explode before stabilizing. Monitor first 10 epochs for NaN.
- If value head is genuinely broken (Phase 1 value training was flawed), enabling it might just pull latent toward a wrong target. Unlikely but possible — Phase 1 value losses were modest.

**Proposed fix task — TASK_736**: re-run Stage B on the 32-ch Phase 1 checkpoint with `--value-weight 0.5` instead of `--value-weight 0.0`. Every other flag identical to TASK_732. This isolates the fix cleanly against the TASK_732 baseline.

If the fix works: ceiling breaks, dir_acc > 0.60, policy_loss drops below log(5). We've been stuck for 6 runs on a single-line config issue.

If the fix doesn't work: value training wasn't the blocker after all, and the latent itself is the ceiling. Then we revisit §46 Tier A (dense oracle), Tier D (more data), or accept ceiling.

Either way: this is the single cheapest experiment available (one flag, no code change, 2hr train), with the highest probability of a decisive result.

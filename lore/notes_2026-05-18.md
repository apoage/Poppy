## §134 — TASK_753 implementation: Bella-as-data augmentation (commit `3b01cc0`)

10 sequential steps (Step 0 was a one-line `_exhausted_groups`
latent-bug fix discovered during P4 review), 9 smokes plus the
Step 8 production-batch smoke, all PASS.

**Three load-bearing deviations from spec:**

1. **`generator.generate(seq_length=1440)` is BROKEN** in the current
   ckpt (raises `ValueError: jnp.pad unsupported pad_width with nd=4`).
   Forced to chained `generate_on_device` calls at native
   `seq_length=400` per chunk. Default `--bella-augment-seq-length=800`
   (2 chunks). Seam tolerance is documented in the SPEC.
2. **Architecture spec was stale**: actual ckpt is 768d/12L conv +
   10 ODE steps, NOT 1536d/16L single-step as `diff_teacher/CLAUDE.md`
   claimed.
3. **C3 "too easy" signal materialized**: per-step oracle PnL ratio
   measured at smoke is **~7× higher on Bella slots than historical**
   (Bella ≈ 0.0124/step vs Historical ≈ 0.0017/step). This is the
   risk the review flagged: Bella's OT-CFM probability flow is too
   smooth/predictable; the path solver finds near-optimal trajectories
   trivially. The SPEC at `experiments/758_bella_augment/SPEC.md`
   includes a "too_easy" tag protocol — at result-authoring time, if
   the ratio holds above 2×, the experiment is tagged but not aborted.

The 7× ratio is the most important signal of this implementation
arc. It says: even if augmentation produces a numerically positive
Alpha at eval, the **learned policy may be Bella-shaped, not real-
market-shaped**. The path-of-least-resistance failure mode is
exactly the one `project_bull_blindness.md` warned about for
synthetic data.

This doesn't kill 753 — augmentation might still be net-positive at
modest ratio (0.25 default) where the historical slots dominate. But
it does say: the result.md verdict for 758 needs careful framing.

Files touched: new `mcts_trader/data/bella_market.py` (373 LOC),
`train_easy.py` (+334/-138 LOC — biggest delta of the session, since

## §138 — Lessons (load-bearing, for memory + future sessions)

1. **Two-gate review protocol works.** Agents writing implementation
   reviews catch 7-9 spec gaps per task on average. Approve the
   in-step mitigations, the agent proceeds to clean implementation.
   Time cost: ~25% of total agent wall, well spent.

2. **The 749 OOM smoke-test rule is now load-bearing**: smoke must
   exercise full `stage_b_train_step` at production batch and
   temporal window. P2 and P4 both used this; both implementations
   came out clean. Memory: `feedback_smoke_test_full_shape.md`
   (TODO save).

3. **Mechanism-class hypothesis is updating in real time.** The
   encoder-aux class is producing consistent negatives; the
   planning-aux class has one survivor. The data-side class is
   new and untested. Future SPECs should specify which class
   they're testing, so we can keep score.

4. **Synthetic data carries hidden "too easy" risk.** The 7×
   oracle-PnL-ratio on Bella slots is a real signal — Bella's
   probability flow is too smooth. Any future synthetic-data
   experiment needs an explicit difficulty calibration before
   training.

5. **Lore as artifact still applies.** Today's notes are 200+
   lines of reversal + verdict + new implementation arc. Even if
   the Bella v2 family closes negative, the methodology
   crystallization (review protocol, smoke discipline, mechanism
   class taxonomy) is the durable output. Publishable as a
   "campaign retrospective" once one mechanism actually promotes.

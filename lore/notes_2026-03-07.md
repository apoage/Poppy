### TASK_704: Historical Data Coverage

Found two coverage gaps:

**1. Window sampling — 18% coverage per period**

`get_window_random()` sampled uniformly at random. With 258K timestamps and ~51K windows per merge, only 18% of data seen before period rotates.

Fix: Sequential scan with stride=length/2 (50% overlap). Full pass through data each epoch. Small jitter on subsequent passes. Coverage logging: `[HISTORICAL] Pass N complete: 1060 windows, stride=244`.

**2. Asset rotation — 1 of 16 subsets used per period**

`HistoricalScheduleManager` ignored `training_runs` in `training_schedule.json`. Created one run per period from `available_assets` (padded to 64). But schedule already has 16 pre-computed runs per period with different 64-asset subsets (30-50% overlap) — same format Bella's `RainbowTableLoader` uses.

Fix: Flatten `training_runs` into individual runs. 18 runs → 270 runs. Each period now cycles through all its asset subsets.

## ML Audit: Expert Imprinting Failure Analysis

**Status: CRITICAL ISSUES IDENTIFIED**

Investigation into "Easy Mode" training revealed three fundamental flaws explaining:
- Model collapse (zero value loss with high MSE)
- Poor policy convergence (~7-8% oracle agreement plateau)

### Root Cause Analysis

#### A. Value Target "Hindsight" Bug (CRITICAL)

| Current | Problem | Required |
|---------|---------|----------|
| `oracle_returns = cumulative_pnl` | Tracks profit from step 0→t | Should predict profit from t→T |

**Impact**: Agent learns to "remember" past performance instead of "plan" for future gains. Value head is useless for MCTS.

**Fix in train_easy.py**:
```python
# OLD: ep_data['returns'] = oracle_returns
# NEW: ep_data['returns'] = oracle_returns[-1] - oracle_returns
```

#### B. Numerical Support Clipping ("Zero Loss" Trap)

| Current | Problem | Observed |
|---------|---------|----------|
| `scaled_returns = returns * 10.0` | PnL of 4.0 → 40.0 (clips to 10.0) | Val MSE ~42, Loss ~0 |

**Impact**: All targets clip to max bin (+10.0). Model predicts constant max → perfect CE loss but massive MSE.

**Fix in easy_trainer.py**:
```python
# OLD: scaled_returns = batch['returns'] * 10.0
# NEW: scaled_returns = batch['returns'] * 2.0
```

#### C. Policy Label Information Bottleneck

| Current | Problem | Impact |
|---------|---------|--------|
| `argmax(policy_targets)` → integer label | Discards k=4 equally-valid actions | Noisy gradients, 7% ceiling |

Oracle selects k=4 assets → at least 4 "correct" Buy/Sell + 60 "correct" Hold actions. Single-label CE penalizes agent for picking 2nd-best asset.

**Fix in easy_trainer.py**:
```python
# OLD: softmax_cross_entropy_with_integer_labels(logits, batch['actions'])
# NEW: softmax_cross_entropy(logits, batch['actions'])  # soft targets
```

### Data Alignment Verification

Verified window alignment in `OnTheFlyGenerator._generate_episode_data`:
- `observations[i]` built from `prices[i : i+60]`
- Oracle action/return at `start_idx + i` where `start_idx = 59`
- **Result: CORRECT** - agent sees 60 steps history, predicts next step action

### Changes Applied (easy_trainer.py)

| Line | Change | Reason |
|------|--------|--------|
| 145-148 | `softmax_cross_entropy` (soft) | Multi-action support |
| 152-155 | Scale 10.0 → 2.0 | Prevent support clipping |
| 165-169 | `argmax(batch['actions'])` for agreement | Soft targets compatibility |
| 173-180 | `batch['actions'] > 0.1` for top5 | Multi-correct actions |
| 183 | Unscale `/2.0` | Match new scaling |

### Changes Applied (train_easy.py)

| Location | Change | Reason |
|----------|--------|--------|
| `_generate_episode_data` | `returns[-1] - returns` | Future PnL, not cumulative |
| `_generate_episode_data` | Pass `policy_targets` not `argmax` | Soft labels (320-dim) |
| `_generate_batch_episodes` | Same as above | Batched version |

**Status: ALL FIXES APPLIED**

## Dual-Branch Training: Literature Context

**How common is this approach?** Uncommon in production, but well-researched.

### Related Techniques

| Technique | Similarity | Used By |
|-----------|------------|---------|
| Federated Learning | Multiple models → periodic merge | Google (keyboard), hospitals, edge devices |
| Population-Based Training (PBT) | Multiple agents, exploit/explore | DeepMind (AlphaStar, Capture the Flag) |
| Self-Play + League | Parallel agents on different opponents | OpenAI Five, AlphaStar |
| Model Soups | Average multiple fine-tuned checkpoints | Google (2022), Wortsman et al. |
| Git Re-Basin / Linear Mode Connectivity | Merge diverged models via weight permutation | Research (2022-2023) |

### e-dojo Approach Combines

1. **Dual data sources** (real + synthetic) - like domain adaptation
2. **Fisher-weighted merging** - from continual learning literature
3. **Automatic divergence-triggered merging** - novel, usually manual in literature

### Why Rare in Practice

- Most teams just mix data in one training run
- Merging diverged nets is tricky (loss barriers, permutation symmetry)
- Requires careful monitoring (divergence metrics, cosine similarity)

### Closest Production Analogs

- DeepMind's league training for games
- OpenAI's curriculum + self-play mixing
- Federated averaging in privacy-sensitive domains

**Assessment:** e-dojo is research-grade. Fisher-weighted merge + adaptive scheduling is more sophisticated than typical federated averaging.

## TASK_671: Bella Return Interpretation Bug (CRITICAL FIX)

### Issue Discovered
During e-dojo training, Bella branch showed 2-3% agreement vs Synthetic's 16-18%.

### Root Cause
`setup.py:650` applied `cumsum` to Bella's output, but Bella outputs **cumulative returns** (trained on `prices/baseline - 1.0`), NOT step returns.

| What Bella outputs | What setup.py did | Result |
|-------------------|------------------|--------|
| Cumulative return from t=0 | `cumsum(output * 0.01)` | Double-cumsum garbage |

### Fix v1 (INCORRECT)
Assumed cumulative returns, but diagnostics showed std ~1.0 (z-scored):
```python
prices = 100.0 * (1.0 + close_prices)  # Caused wild swings [-150, 1250]
```

### Fix v2 (CURRENT)
Scale z-scored output to realistic step returns:
```python
volatility_scale = 0.015  # Target ~1.5% step volatility
step_returns = close_prices * volatility_scale
log_prices = jnp.cumsum(step_returns, axis=1)
prices = 100.0 * jnp.exp(log_prices)
```

### Diagnostic Added
Set `BELLA_DEBUG=1` environment variable to see output ranges:
```bash
BELLA_DEBUG=1 python train_easy.py --bella --epochs 1
```

### Diagnostic Output (BELLA_DEBUG=1)
```

close_prices mean: 0.13-0.14
close_prices std: 1.05
```
- Bella outputs z-scored/standardized values (std ~1.0), NOT raw cumulative returns
- Fix v1 assumption was wrong → Fix v2 scales appropriately

### Scaling Verification (Fix v2 Confirmed Working)

```python
if self.launcher is not None:
    health = self.launcher.check_health()

    if all_done:
```

### Behavior

- When both branches show "completed" or "failed", prints summary and exits

## TASK_672: Merged Checkpoint Not Loading (CRITICAL FIX)

### Issue Discovered
After 5 merges, branches still diverging (cosine 0.72 → 0.30). Bella stuck at 2%, Synth at 16%.

### Root Cause
`check_and_merge()` saves merged checkpoint but **never restarts branches** to load it. Branches continue training with their old weights.

### Fix Applied
Added `restart_both_with_checkpoint()` to `TrainingLauncher`:

```python
# After merge completes in check_and_merge():
if self.launcher is not None:
    self.launcher.restart_both_with_checkpoint(str(merged_path))
```

The method:
1. Stops both branches gracefully
2. Waits for cleanup
3. Restarts with explicit `--checkpoint` pointing to merged weights
4. Stagger of 5s between restarts

### Files Modified
- `tools/orchestration/e-dojo_v1.py`
  - Added `launch_params` storage in `TrainingLauncher.__init__`
  - Store params in `launch_dual_branches()`
  - Added `restart_both_with_checkpoint()` method
  - Call restart after merge in `check_and_merge()`

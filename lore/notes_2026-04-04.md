## Session 44 — Stage B Full Run Debugging + TASK_718 Spec

### TASK_716g: Stage B Full Run — BLOCKED (value stalling)

Launched full Stage B run (1000 epochs, 400 steps/epoch, batch 256, 32 MCTS sims).

**Crash 1: `copy_stream->WaitFor(compute_stream)` abort (E7)**
- Root cause: CPU->GPU transfers (`jnp.array()` in `generate_batch`) colliding with async GPU compute from MCTS/training
- Fix attempt: Added `jax.block_until_ready(metrics)` after train step to fence GPU

**Crash 2: `CUDA_ERROR_ILLEGAL_ADDRESS` (E7)**
- Root cause: `TF_GPU_ALLOCATOR=cuda_malloc_async` causing memory corruption under heavy allocation churn (~100k small GPU ops per epoch from 17 slots x 400 steps x 2 encodes + MCTS)
- Fix: Removed `cuda_malloc_async`, added `XLA_PYTHON_CLIENT_PREALLOCATE=true` with 85% VRAM fraction
- Result: **Stable past E144+** — no more crashes

**Background thread crash (reverted)**:
- Added `PrefetchGenerator` with background thread for batch generation
- Crashed immediately — JAX GPU ops (`jnp.array`, `jit_batch_encode_temporal`) from background thread collide with main thread GPU ops. JAX is NOT thread-safe for GPU operations.
- Removed; direct `generate_batch` calls work fine (gen=0.2s with prefetch was nice but gen=28s without is acceptable given mcts=36s is the real bottleneck)

### Training Stall Analysis

Stage B ran to E144+ without crashes, but training stalled:

```
E0-5:   total=5.2-7.4 (initial convergence)
E17-22: policy=1.40, value=0.007, grad=0.5 (COLLAPSED)
E30+:   policy~2.0, value~2.0, grad~17 (recovered but oscillating)
E140:   policy=1.98, value=1.48 (no improvement since E5)
```

**Root cause diagnosis — two compounding issues:**

**1. Reward signal vanishes in TD targets**
- `r_step = rewards_dynamics / 100.0` → per-step PnL of 0.001 becomes 0.00001
- Value support bin width = 0.05 → reward is 5000x smaller than one bin
- TD target collapses to `td ≈ 0.997 * V(s_next)` — self-consistency, no reward signal

**2. Value head saturated from Phase 1**
- Phase 1 trained on `oracle_returns * 2.0` → range [0, 10]
- Value predicts ~10.0 for everything → MCTS root_value constant
- Search can't discriminate states → visit counts are just noisy policy prior

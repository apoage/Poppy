## CRITICAL BUG: State Channels Wired to Oracle (TASK_692)

### The Fundamental Problem

State channels were designed to give the model memory of its **own** past actions. Instead, they were wired to the **oracle's** trajectory:

```python
# train_easy.py line 398-417 (THE BUG)
target_position = compute_target_position(oracle_selections, log_returns)
state_channels = build_state_channels(target_position, ...)
```

The model receives oracle memory as input and is asked to predict oracle actions as output. It learns to parrot oracle patterns, not to make autonomous decisions. At inference, oracle state is gone → model sees its own messy state → anti-correlated predictions → catastrophic loss.

**TASK_691 (oracle entropy) was wrong fix** — corrupting 15% of oracle selections doesn't simulate model-generated state. The oracle should NEVER touch state channels.

### Correct Design

```
model forward[t-1] → action → update_state → state[t-1] → model input[t]
oracle → training targets ONLY (never touches state)
```

Task spec: `tasks/TASK_692_FIX_MEMORY_THAT_CLAUDE_FUCKED_UP.md`

- Training loop calls `set_model_params()` each epoch

### TASK_693: Adversarial Review Found 4 Bugs in TASK_692

Deep review of TASK_692 against the codebase found the rollout would recreate the
same train-inference mismatch it was designed to fix:

**Bug 1 (CRITICAL): Absolute vs incremental position stepping.**
`action_type_to_position()` mapped Buy→+1 always, Sell→-1 always (absolute).
Benchmark uses incremental: Buy means "step toward long" (short→flat→long).
Example: model is short(-1), decides Buy → training rollout jumps to +1 (flip),
benchmark steps to 0 (close short). Different position, PnL, heat, everything.

**Bug 2 (MEDIUM): Confidence channel hardcoded to zero.**
Channel 33 was `jnp.zeros()` during training rollout but `max(softmax)` at inference.

**Bug 3 (LOW): Wasted oracle state computation.**
`_generate_episode_data()` computed oracle state channels then immediately overwrote
them with model rollout output.

**Bug 4 (CRITICAL): State channel slicing out of bounds.**
Oracle `build_state_channels` produces T entries (one per return timestep).
Model rollout produces n_valid entries (one per observation window, n_valid = T - ws).
Both paths used `state_channels[ws-2:end_idx-1]` — works for T-length oracle output,
goes out of bounds for n_valid-length model output (ws=64, so index 62+ on array of
length T-64).

### Fixes Applied

| Bug | Fix |
|-----|-----|
| 1. Position semantics | Deleted `action_type_to_position()`. Replaced with `jnp.minimum(pos+1, 1)` / `jnp.maximum(pos-1, -1)` — matches `benchmark_easy.py:529-537` |
| 2. Confidence channel | `jnp.max(jax.nn.softmax(logits))` per asset. `_build_model_state_trajectory` now returns `(state, confidence)` tuple |
| 3. Wasted computation | Restructured `_generate_episode_data`: `if use_model_rollout: ... elif use_state_channels: ...` — no oracle state when model rollout active |
| 4. Slicing mismatch | Model rollout: `state_channels[:n_windows]`. Oracle: `state_channels[start_idx-1:end_idx-1]`. Both paths in `_generate_episode_data` and `_generate_batch_episodes` |

Also fixed: double-JIT on `_build_model_state_trajectory`, `observations` undefined
variable in single-episode model rollout path (dead code but corrected).

## Session 5a — Paper Review: RL²F (arXiv:2602.16066v1)

Read *"Improving Interactive In-Context Learning from Natural Language Feedback"* (Klissarov et al., Google DeepMind, 2025). Located at `docs/arXiv-2602.16066v1/`.

**Core idea:** Train LLMs to learn from corrective feedback in multi-turn didactic interactions. Teacher has privileged info (ground truth), student iterates. RL over multi-turn conversations yields "in-context plasticity" — the model actually changes its answer instead of repeating. Smaller model (Flash) nearly matches model 10x larger (Pro).

**Key result — Autodidact:** Training the student to predict the teacher's feedback (world-modeling objective) lets the model self-correct at inference without a teacher. The autodidact **outperforms** the teacher-student setup.

**Relevance to Foxglove:** Structural parallels are strong — our oracle is the "privileged teacher," autoregressive rollout is the "multi-turn interaction," value head is the "world model." The paper validates our Phase 3 design (MCTS self-play surpassing oracle). Core mechanism (language feedback) doesn't transfer to numeric tensor agents, but the autodidact pattern does.

**Action taken:** Created TASK_695 — auxiliary oracle mask prediction head. Small MLP predicting oracle's top-k selection mask from shared representation. Trains alongside policy/value in Phase 1; acts as internalized oracle critic during Phase 3 MCTS search. Updated `docs/easy_mode.md` Phase 3 section with autodidact mechanism detail.

## Session 6 — TASK_695: Oracle Mask Prediction Head

Implemented the auxiliary oracle mask prediction head designed in Session 5a. Committed as `77cb089`.

### What it does

2-layer MLP (`Dense(256) → ReLU → Dense(64)`) attached to the latent state. Predicts the oracle's binary top-k selection mask via sigmoid BCE loss. Gives the model an internal "what would the oracle pick?" signal — useful for Phase 3 MCTS self-play (autodidact pattern from RL²F paper).

### Changes

| File | Change |
|------|--------|
| `easy_config.py` | +3 config fields (`use_oracle_mask_head`, `oracle_mask_hidden_dim`, `oracle_mask_weight`) |
| `mcts_trader/jax_agent/muzero_model.py` | +MLP head, `oracle_mask_prediction()` method, wired into `initial_inference`/`prediction_only`/`initialize_parameters` |
| `easy_trainer.py` | Pass config to model, +BCE loss + accuracy metrics, fix warmup_steps > total_steps crash |
| `train_easy.py` | +`--oracle-mask-head` CLI flag, thread `oracle_mask` through single-ep/batch-ep/buffer-sampling |
| `tools/benchmark_easy.py` | Pass config to `create_model()`, collect mask preds, +`oracle_mask_accuracy` in `PeriodResult` |

- **+33,088 params** when enabled (64×256 + 256 + 256×64 + 64), 0 when disabled

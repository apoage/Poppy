### Root Cause Analysis

Identified three oracle bugs causing 21% ceiling:

1. **Hyperactive Agent** - Oracle always picked exactly k=4 assets every step
   - Never output HOLD or "stay flat"
   - Agent learned it must trade every minute

2. **Stateless Oracle** - Oracle didn't know current positions
   - When asset exits selection: output HOLD (wrong!)
   - Should output SELL to close long, BUY to close short

3. **No Profitability Threshold** - Trade even for 0.01% gains
   - Transaction cost is 0.1%, so many trades were unprofitable

## Bug Fixes

### 1. e-dojo Log File Handle Bug
**Location**: `tools/orchestration/e-dojo_v1.py:754`

**Problem**: Log file opened with `with open()` which closed the file handle immediately after Popen, causing Branch A logs to be empty.

**Fix**: Keep file handle open for subprocess lifetime:
```python
# Before (broken)
with open(log_file, 'w') as f:
    proc = subprocess.Popen(..., stdout=f, ...)
# File closes here, subprocess has nowhere to write!

# After (fixed)
f = open(log_file, 'w')
proc = subprocess.Popen(..., stdout=f, ...)
proc._log_file = f  # Keep handle open
```

## 59. TASK_739 killed — ε pathology (2026-04-23 23:35)

TASK_739 (dense sign oracle) was launched first per the overnight sequence. Three independent bugs surfaced before training could even start:

1. **NameError**: agent passed `max_len=max_len` at `train_easy.py:631`, but `max_len` was never defined in that scope. Crashed pool build on first attempt.
2. **DEFAULT_MAX_PATH_LEN too small**: my first fix (drop the arg) used `DEFAULT_MAX_PATH_LEN=512` from `path_solver.py`; sequences are 258k+ rows, so `padded.at[:T].set(returns)` broadcasted (258863, 64) into (512, 64) and errored.
3. **Right fix**: compute `ds_max_len = max(262144, ((T_ret+1023)//1024)*1024)` inline in the dense_sign branch, mirroring the formula at `train_easy.py:701` used by `greedy_lookahead_path`. That matches existing JIT shape so only one compile per unique max_len bucket.

After the fix, training did start, but the **learning dynamics were pathological**:
- E0:  `policy=3.24`, `bc=1.54`
- E5:  `policy=1.6098`, `bc=1.5423`
- E10: `policy=1.6098`, `bc=1.5408`
- E20: `policy=1.6095`, `bc=1.5414`

`policy_loss` locked at `log(5) = 1.6094` to 4 decimals across 15 epochs. TASK_736's comparable trajectory dropped 1.612 → 1.579 over 49 epochs (100× faster). The value head IS training (value 11.6 → 3.8), so this is NOT a TASK_736-style broken ExIt. It's purely a label-quality problem.

**Root cause**: ε=1e-4 is too tight for the actual cumulative-return distribution. On a synthetic smoke test with vol=0.001/step, ε=1e-4 produced ~49% SELL / 2% HOLD / 49% BUY — so per-asset labels alternate nearly randomly as the noisy 20-step cumulant crosses zero, and the per-asset BC gradient averages to zero over time. The policy has no pull toward any action → stays uniform → MCTS visits stay uniform → self-reinforcing.

The spec's "first-pass starting point" ε=1e-4 was under-calibrated. For real minute-bar crypto (vol ~0.001–0.003/step → 20-step cum std ~0.005–0.013), **ε ≈ 5e-3 to 1e-2** is the plausible starting range to hit the 5–15% trade density the spec targets. This needs a dedicated re-run, not a rush-in during the overnight window.

**Decision**: killed the 739 python at E20; the `run_overnight.sh` wrapper fell through to Phase 2 (TASK_737) automatically per its `|| WARNING` fallback. No harm to 737.

Will retry TASK_739 as a standalone run on the next available cycle with ε=5e-3 (or calibrated from a quick script that computes empirical cum-return std on our data and picks ε for target trade density).

## 66. TASK_741 designed (2026-04-25 ~07:25) — codename Mint

Per-asset scalar injection architectural fix. Designed by high-effort agent based on TASK_733's "architecture caps at 87% with cheat" finding. Output: `tasks/TASK_741_PER_ASSET_INJECTION_FIX.md` (231 lines, full spec quality).

**The hypothesis**: V3 minGRU temporal pool partially averages broadcast-scalar input channels (DC offset → recurrent attenuation). Even ground-truth cheat dilutes to 87% extractable.

**The fix**: FiLM (Feature-wise Linear Modulation) injection POST-temporal-pool, ON `per_asset_feats: (batch, n_assets, embed_dim)` at `trm_encoder_v3.py:149` (after LN, before `global_proj`). New `FiLMProjector` flax Module, 2-layer MLP from scalars `(B, A, n_scalars)` → `(γ, β)`, applied as `(1+γ)·feats + β`. Zero-init final Dense → byte-identical default behavior, opt-in via `--per-asset-injection`.

**Why FiLM and not concat+linear**: concat+Dense re-introduces the dilution problem — scalar averaged into a larger vector. Multiplicative scaling forces each scalar to act on every feature dim explicitly. Cross-attention from scalars rejected — conflicts with `mcts_trader/CLAUDE.md`'s "no attention in reasoning" rule.

**Validation plan (3 gates)**:
1. **Re-run TASK_733 cheat with `--per-asset-injection`**. Spec gate: Val Agree ≥ 95%. **Binary falsifier** — if it stalls at 87% again, the hypothesis was wrong, abandon the design.
2. **Re-run TASK_739 dense_sign with `--per-asset-injection`**. Spec gate: dir_acc > 0.62.
3. **Benchmark Gate-2 winner**. Targets per TASK_736 framework.

**Channels 27-31 (cross-sectional, TASK_732)** stay as input channels for the first cycle — additive A/B against existing baseline. Removal is post-validation cleanup.

**One open design question** the agent flagged: cross-asset attention at line 146 might already be smoothing what FiLM is meant to sharpen. Spec defers an "inject before cross-attn" experiment as a follow-up; first run uses canonical post-LN ordering.

**Estimated cost**: ~150-200 LoC, ~3 days dev + ~6 hr training to first answer (Gate 1).

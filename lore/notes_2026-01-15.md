## Technical Notes

### How Adaptive Noise Works

```python
# Each epoch:
controller.update(epoch_reward)

# If reward_ema > target_high (20):
#   Increase difficulty in priority order:
#   1. Price noise (0 → 1.0)
#   2. Temporal jitter (0 → 5 steps)
#   3. Time dilation (0 → 0.3)
#   4. Phase shift (0 → 0.5)

# If reward_ema < target_low (10):
#   Decrease in reverse order
```

### Noise Applied Per-Level

Each generator now calls `_apply_all_noise(prices, pattern_period=X)`:
- L3 (trends): period=50
- L4 (rotation): period=100
- L5 (pairs): period=50
- L6 (triangle): period=30
- L7 (index): varies by component
- L8 (momentum): period=20 (LOOKBACK)
- L9 (mean_rev): period=5 (1/theta)
- L10 (breakout): period=50
- L11 (bid_ask): period=10
- L12 (imbalance): period=20
- L13 (market_making): period=20
- L14 (vol_cluster): period=50

### Why This Should Help H1/H2

- Temporal jitter: Can't rely on exact timing → need to reason
- Time dilation: Patterns appear at different speeds → need adaptation
- Phase shift: Pattern phase changes mid-episode → need re-detection

These force the model to actually USE the intermediate reasoning cycles instead of shortcutting to H3.

### Magic Fill Bug (CRITICAL)

**The Problem:** Limit orders filled at market close price instead of limit price.

```python
# Scenario:
# - Current price: $100
# - Agent places: Limit Buy at $98
# - Price crashes to: $90

# BUG BEHAVIOR:
can_fill($90) → True  # (90 <= 98)
_fill_limit_order(..., price=$90)  # Fills at $90!

# REALITY:
# Price crosses $98 on way down → fills at $98
# Agent should own at $98, not $90
# Bug gave free $8 per share "magic alpha"
```

**Impact:** Model learned that limit orders = free money. Would overuse them in training, then underperform live when magic fills disappear.

**Files Fixed:**

| File | Line | Before | After |
|------|------|--------|-------|
| `vectorbt_env.py` | 781 | `_fill_limit_order(order, price)` | `_fill_limit_order(order, order.limit_price)` |
| `jax_trading_env.py` | 526 | `min(order_price, market)` | `order_price` |
| `jax_trading_env.py` | 536 | `max(order_price, market)` | `order_price` |

**Note:** JAX env had comments claiming this was intentional ("TASK_050 FIX: better price for buyer"). Those comments were WRONG - "better price" creates unrealistic alpha.

### Ghost Order Bug (Bug #2)

**The Problem:** Market orders don't cancel pending limit orders for the same asset.

```python
# Scenario:
# 1. Agent places Limit Buy at $98 (reserves cash)
# 2. Agent does Market Buy at $100 (opens long)
# 3. Old Limit Buy still pending!
# 4. Price dips to $98 → Limit Buy fills
# 5. Result: Double exposure or unexpected position change
```

**Impact:** Stale orders could unexpectedly fill later, causing position chaos.

**Files Fixed:**

| File | Function | Fix |
|------|----------|-----|
| `vectorbt_env.py` | `_execute_buy()` | Cancel pending + refund cash |
| `vectorbt_env.py` | `_execute_sell()` | Cancel pending + refund cash |
| `jax_trading_env.py` | `execute_buy()` | Set `order_active[asset] = False` |
| `jax_trading_env.py` | `execute_sell()` | Set `order_active[asset] = False` |

### Lazy Execution (Enhancement to Ghost Order fix)

Changed vectorbt_env to match JAX env's lazy execution model:

**Before:** Cash reserved at order placement, refunded on cancel/expire
**After:** No cash reserved, availability checked at fill time

**Benefits:**
- Simpler logic (no tracking of reserved cash)
- More realistic (real exchanges don't lock your funds for limit orders)

### Bug #4: Phantom Tax (JAX env)

**The Problem:** JAX env calculated borrow_cost and subtracted from reward, but never deducted from state.cash.

```python
# BEFORE:
portfolio_change = new_portfolio_value - prev - borrow_cost  # Penalize reward
# But state.cash unchanged! Agent keeps all money.

# AFTER:
new_state = new_state.replace(cash=new_state.cash - borrow_cost)
new_portfolio_value -= borrow_cost
portfolio_change = new_portfolio_value - prev  # Natural penalty
```

**Impact:** Agent got "bad grades" for shorting but kept all money. Could hold shorts indefinitely without margin drain.

### Bug #6: Geometric Reward Bias (Both envs)

**The Problem:** symlog applied to arithmetic returns creates bias toward volatility churn.

```python
# Start: $100
# Step 1: +50% -> $150. symlog(50) ≈ 3.93
# Step 2: -33% -> $100. symlog(-33) ≈ -3.53
# Net wealth: $0 change
# Net reward: +0.40 (positive!)

# Agent learns: "Going up and down is better than flat"
```

**The Fix:** Use log returns FIRST (geometrically correct), THEN apply symlog (compression).

```python
# Log returns are symmetric:
# log(1.5) * 100 = +40.5
# log(0.66) * 100 = -40.5
# Net: 0 (correct!)

# Then symlog for MuZero value support compression
log_return = np.log(new_value / prev_value) * 100.0
reward = symlog(log_return)
```

**Fixed in:** Both `vectorbt_env.py` and `jax_trading_env.py`

### Bug #7: Value Support Mismatch (Config)

**The Problem:** VALUE_SUPPORT [-10, 10] assumes PopArt normalization, but PopArt defaulted to False.

```python
# Without PopArt:
# - Reward per step: symlog(log_return) ≈ [-4, 4]
# - Value (sum with γ=0.997): [-400, 400]
# - Support: [-10, 10]
# - Result: Massive clipping, agent can't distinguish values

# With PopArt:
# - Values normalized to N(0, 1)
# - 99.7% of values fit in [-3, 3]
# - Support [-10, 10] is plenty of headroom
```

**Fix:** Changed `--use-popart` default from False to True.

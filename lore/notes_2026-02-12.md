## TASK_156: Action Representation Bug (BENCHMARK FIXED)

### Problem
Model trained on Bella performed WORSE on Bella than on synthetic data it never saw.
- BUY agreement: **0%** on Bella (model never outputs BUY)
- SELL agreement: 22.8%
- Model P&L: -3597% (severely negative)

### Root Cause
State-aware oracle mismatch:
- Training uses `state_aware_oracle=True` (transition-based actions)
- Benchmark was using stateless oracle (return-sign-based actions)

| Action | Training Meaning | Benchmark (Wrong) |
|--------|-----------------|-------------------|
| BUY | Open long, close short | Selected + positive return |
| SELL | Open short, close long | Selected + negative return |

### Fix Applied
Updated `benchmark_oracle_vs_model.py`:
1. `oracle_selections_to_actions_single()` - tracks position state (-1/0/+1)
2. `simulate_model_pnl()` - uses state-aware position transitions

### Results After Fix

| Metric | Before | After |
|--------|--------|-------|
| BUY Agreement | 0% | **5.1%** |
| Model outputs BUY | NO | YES |

**Conclusion:** Benchmark bug fixed. Remaining low agreement is training quality, not benchmark issue.

## TASK_157: Oracle K and Adaptive Weight Analysis (NEW)

### Root Cause of Model Overtrading

Investigation revealed why model trades 10× more than oracle but with only 1.1% precision:

**Configuration Chain**:
```
oracle_k=1 → 1/64 = 1.5% selection → ~1% after threshold filtering → 99% HOLD
```

**Adaptive Weight Effect (TASK_149)**:
```python
# easy_trainer.py lines 154-173
target_trade_weight = n_holds / n_trades  # ≈ 63/1 = 63×
loss_weights = jnp.where(is_trade, adaptive_trade_weight, 1.0)
```

**The Paradox**:
| Training Signal | Model Interpretation |
|-----------------|---------------------|
| "Trades get 63× gradient" | "Trading is very important" |
| "Only 1% are trades" | "I should trade more than 1%" |
| Result | 10% trades, 1.1% precision |

### Benchmark Evidence

```
Oracle Trade Rate:  1.0%
Model Trade Rate:   10.1% (10× oracle!)
Trade Precision:    1.1%  (essentially random)
```

Model learned to trade MORE but not WHEN.

### Recommended Fixes

1. **Cap adaptive weight** at 10× (not 63×)
2. **Increase oracle_k** to 5-10 for more trade signal
3. **Consider focal loss** for principled imbalance handling

Full analysis in: `tasks/TASK_157_ORACLE_K_AND_ADAPTIVE_WEIGHT.md`

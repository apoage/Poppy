## Session 23 — TASK_701: Foxglove Data Pipeline Audit & Patches

### 3-Way Audit

### Patches Applied (TASK_701 + TASK_700)

| Patch | File | What |
|-------|------|------|

| PATCH-10 (P3) | `train_easy.py` | Remove dead `_generate_episode_data()` (~200 lines) |

### Key Insight

The critical bug (PATCH-1) was that `get_window()` returns `(T, 64)` but up to 33 columns are
all-zeros in early periods (pre-2020). The existing safety net checked `shape[1] < 64` which is
always False because the cache pre-allocates 64 columns. The fix detects zero *content* and
cyclically duplicates live columns, matching the reference implementation in `setup.py:408-413`.

### Cache Rebuild

Rebuilt npz cache after PATCH-3 backward-fill:
- Old cache: 5,613,837 timestamps (with leading zeros in late-listing assets)
- New cache: 3,824,428 timestamps, 64 assets, all first-valid = 2016-04-12
- 0/64 late-listing assets — backward-fill ensured every column has data from the start
- Timestamp reduction likely due to `min_required_assets` filter being stricter now
- `asset_first_valid_ts` metadata saved in cache (PATCH-7)

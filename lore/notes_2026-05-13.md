## 100. Bella precompute — TASK_740 Step 1 FAILED + scale issue

Server agent launched the precompute on GPU 3 last night with
`--bella-checkpoint checkpoints/diff_teacher/final/generator`. It ran for
8.3 hours processing the first period (258,803 windows × k=4 samples,
8.6 w/s), wrote the 250 MB shard successfully, then crashed on manifest
assembly:

```
File "tools/precompute_bella_predictions.py", line 210, in _process_period
  return {'path': str(out_path.relative_to(REPO_ROOT)), ...
ValueError: 'data/bella_preds/bella_preds_2018-10-17__2019-04-15.npz'
is not in the subpath of '/home/operator/Trader'
OR one path is relative and the other is absolute.
```

### Bug

Line 244: `out_dir = Path(args.output_dir)` constructs `out_dir` as
**relative**. `out_path = out_dir / "name.npz"` stays relative. Then
`out_path.relative_to(REPO_ROOT)` fails because `REPO_ROOT` is absolute
(line 52: `Path(__file__).resolve().parent.parent`).

**Fix** (one line): `out_dir = Path(args.output_dir).resolve()`.

The completed 250 MB shard is preserved on disk at
`~/Trader/data/bella_preds/bella_preds_2018-10-17__2019-04-15.npz`. On
re-run, `_process_period` short-circuits via `out_path.exists()` (line
153) → no re-compute.

### Scale issue (the real blocker)

- `config/foxglove_periods.json` has **270 periods**.
- Each ~6-month period has ~258,803 minute-bar windows × k=4 samples.
- Measured: ~8.6 windows/sec → ~8.3 hours per period.
- Naive projection: **270 × 8.3 ≈ 2,241 hours = 93 days of GPU compute.**
- Storage: 270 × 250 MB = **~68 GB** of preds.
- SPEC's "30-60 min" estimate is off by ~3 orders of magnitude.

The path fix alone doesn't make TASK_740 executable. The precompute
design needs minimum-viable rethink (likely: stride windows so we don't
predict every minute, fewer K samples, or limit periods).

# Session Notes - 2026-02-03

## TASK_138: BC Loss Zero Bug - Investigation & Fix

### Problem
After 24-hour overnight dojo run:
- `bc_loss`: 0.0 across all epochs
- `expert_batch_size`: 0 (nothing being sampled)
- `expert_demo_count`: 16605 → 50000 (demos ARE being stored)
- Model showing poor results: -14620% alpha, value MSE=11

### Root Cause Found
**`_compressed_obs` dict was NOT being cleared by `clear()`**

When buffer is cleared (noise change, level switch, regeneration):
1. `_episode_prices.clear()` - prices cleared
2. `_next_episode_id = 0` - IDs reset
3. `_compressed_obs` - **NOT cleared!** (BUG)

Result: Stale compressed observations persist, causing mismatches when new episodes reuse the same IDs.

### Fix Applied
**File**: `mcts_trader/jax_agent/expert_buffer.py`

Added to `clear()` method:
```python
# TASK_136a FIX: Also clear compressed observations!
compressed_mb = self.get_compressed_obs_mb()
self._compressed_obs.clear()
```

### Files Modified
1. `mcts_trader/jax_agent/expert_buffer.py`
   - Added `self._compressed_obs.clear()` to `clear()` method
   - Improved logging message to show compressed obs MB cleared

### Verification
Test run with `--steps 200 --imprint`:
- `demo_count`: 417 → 834 (demos accumulating correctly)
- `compressed`: 3 → 6 (compressed obs being stored)
- `sample_batch()` returning valid batches (no "Returning None")

### Note on Configuration

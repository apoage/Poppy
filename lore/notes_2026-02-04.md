### Architecture

```
Easy Mode Pipeline:
```

### Bug Fix During Implementation

**Issue**: `flax.errors.ScopeParamNotFoundError` when calling `model.apply()` with method-specific calls.

**Cause**: Model params initialized with `mode='initialize_parameters'` are structured for `__call__`, not individual methods.

**Fix**: Use `model.apply({'params': params}, observation=obs, mode='initial_inference')` instead of `method=self.model.representation`.

## Evening Session: On-the-Fly VRAM Generation & Validation

### Major Refactor: train_easy.py

Rewrote `train_easy.py` to use on-the-fly VRAM generation following the efficiency philosophy:
- **GPU Cache**: Legendary resource - don't touch
- **VRAM**: Use when available, prefetch data here
- **RAM**: Second-class data, batch transfers
- **Disk**: Control data only, load to RAM for compute
- **Stream**: Last resort

Key changes:
1. **Deleted `generate_oracle_data.py`** - wasteful disk I/O
2. **Created `OnTheFlyGenerator`** class with:
   - Background ThreadPoolExecutor for price prefetching (2 workers)
   - 8-episode VRAM buffer
   - Vectorized price extraction (np.stack)
   - Zero-copy JAX pipeline (no np.array roundtrips)
3. **Added XLA optimizations** from train_jax_fast.py:
   - XLA autotuning cache
   - TF_CPP_MIN_LOG_LEVEL=2 (suppress warnings)
   - JAX compilation cache

## Late Session: Audit-Driven Optimizations

### Optimizations Implemented (from Audit Report)

| Fix | Description | Impact |
|-----|-------------|--------|
| **Latent State Caching** | Pre-compute encoder output in buffer, use `prediction_only` mode | Removes TRM from training loop |
| **N_BUFFER: 8 → 32** | Increased episode diversity | Better gradient quality |
| **`--no-latent-cache` flag** | Toggle for debugging | Flexibility |

### Model Changes

**`mcts_trader/jax_agent/muzero_model.py`**:
- Added `prediction_only` mode that skips encoder, directly uses cached latent states

**`easy_trainer.py`**:
- `_train_step_impl` now accepts `use_latent_cache` flag (static for JIT)
- Automatically detects `latent_states` in batch and uses `prediction_only` mode

**`train_easy.py`**:
- `OnTheFlyGenerator.set_encoder()` enables latent caching after trainer creation
- Pre-computes latent states for buffer entries during initialization
- `generate_batch()` returns `latent_states` when caching enabled

### Why Oracle Optimization Was Skipped

The oracle (`greedy_lookahead_path`) is already JIT-compiled and runs **once per episode**, not per training step. With N_BUFFER=32 and SAMPLES_PER_EPISODE=200:
- Oracle runs ~32 times per 6400 training samples
- Marginal impact on total training time
- Complexity/benefit ratio not worth it

### Verification

```bash
# With latent caching (default)
python train_easy.py --preset small --epochs 10 --levels 0 --steps-per-epoch 50
# → "Latent state caching enabled (32 episodes cached)"

# Without latent caching (for comparison)
python train_easy.py --preset small --epochs 10 --levels 0 --steps-per-epoch 50 --no-latent-cache
```

Both run at ~3.0s/epoch for small model. Larger models will see more benefit from latent caching.

## Research: DeepSeek-R1 Paper Analysis

### Paper Review

Reviewed DeepSeek-R1 paper (`docs/research/arXiv-2501.12948v2/sn-article.tex`) - their approach to training reasoning through pure RL.

**Created**: `tasks/TASK_139_GRPO_DEEPSEEK_R1.md`

### Key Techniques Identified

1. **GRPO (Group Relative Policy Optimization)**
   - No critic/value network needed
   - Advantage = `(r_i - mean(rewards)) / std(rewards)`
   - Simpler than PPO, proven at 671B params
   - Paper ref: `sn-article.tex:217-232`

2. **Large Clip Ratio**: ε = 10 (vs PPO's 0.2)
   - Paper ref: `sn-article.tex:393-394`

3. **Rule-based rewards over neural reward models**
   - Avoids reward hacking at scale
   - Aligns with our PnL/Sharpe approach

**Major finding**: Our `ALPHAZERO_TRADING_VISION.md` (Dec 19, 2025) independently arrived at same conclusions as DeepSeek-R1 (Jan 2025).

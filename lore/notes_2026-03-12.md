## Session 31 — TASK_707: Period Cycling for Foxglove

### Issue: Overfitting from Single-Period Training

Training was stuck on one period (2018-10-17 → 2019-04-15, 61 assets) for 790+ epochs because `HistoricalScheduleManager.advance()` is only called after merges (dual-branch mode). In single-branch mode the cursor never moved.

Result: training agreement 94% ↑ while benchmark PnL -75% → -388% ↓.

Dojo v3 already solved this with `--periods-file` + stratified cycling in `train_jax_fast.py`. We adapted the same pattern for Foxglove.

### TASK_707: Period Cycling — DONE

**Design**: Load all 270 training runs (18 periods, 2018-2025) into RAM at startup, cycle through them round-robin each epoch inside `train_easy.py`. No subprocess restarts.

**Changes:**

1. **`mcts_trader/data/history.py`**: Added `close_db()` — frees DB connection after RAM cache loaded (important when loading 270 markets)

2. **`train_easy.py`**:
   - New `--periods-file` CLI flag — JSON with multiple periods
   - `OnTheFlyGenerator` now accepts `historical_markets` list
   - `advance_period()` method — cycles to next period, flushes buffer, refills from new data
   - Called every epoch in `train_epoch()`
   - Val generator offset by half for diversity
   - Resume sets period offset to `start_epoch % n_periods`

3. **`tools/orchestration/e-dojo_v1.py`**:
   - Single-branch historical path now generates `/tmp/foxglove_periods.json` with all runs
   - Passes `--periods-file` instead of `--start-date`/`--end-date`
   - `launch_branch()` supports `--periods-file` passthrough

### Fix: Auto-Resume Picking Merged Instead of Branch Checkpoint

Single-branch mode was resuming from `merged_latest.pkl` (epoch 4339) instead of `phase1_epoch4754.pkl` (latest branch checkpoint). Fixed `launch_branch()` auto-resume logic:
- Single-branch mode: checks own output dir first (`jax_ckpt_easy_A/branch_A_historical/*.pkl`)
- Falls back to merged only if no branch checkpoint exists (first launch)
- Dual-branch mode: unchanged

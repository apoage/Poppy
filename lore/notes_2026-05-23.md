Both phases ran cleanly in parallel — read-only agents do not conflict on the working tree.

**Consolidated verdict (cross-validated):**

- **1 confirmed P0** — `767/F1`. `mcts_trader/jax_agent/factored_search.py:128-131` `_q_to_policy` runs `q_centered = q_values - q_values.mean(axis=-1)` then softmax. When `disable_limit_orders=True`, limits are masked to `-1e9` → per-asset mean ≈ `-4e8` → float32 ULP at that magnitude is 32 > the range of valid Q's (|Q|≤20) → all three valid `q_centered` entries collapse to the same float32 → softmax output becomes uniform `[1/3, 1/3, 1/3, 0, 0]` across valid actions. The **policy training target degenerates to random uniform**; 767 would have trained a random policy and looked like a null. Action *selection* (`argmax` on un-centered values) was unaffected; only the *learning signal* was destroyed. Cross-validator independently re-derived every ULP step, confirmed XLA does NOT optimize the mean-shift away (`jax.nn.softmax`'s internal max-shift operates on whatever input it gets), confirmed the epsilon-greedy mix accidentally matches the bug. Smoking-gun metric: `mean_trade_rate = 0.667 ± 0.02` (2/3 active under uniform sell/hold/buy); the 767 ship-smoke logged `limit_action_fraction = 0.000` (consistent with both correct and buggy) but did NOT report `mean_trade_rate`, so the bug slipped through. **Fix: one line — drop the mean-shift entirely; `jax.nn.softmax` does its own max-shift; the mean is mathematically redundant + bit-identical via shift-invariance.**

- **6 P1s** — `767/F2` (mctx interior priors unmasked at depth ≥1 — wastes search compute and biases value backup); `di/F1` (sqlite3 crash silent abort under `set -euo pipefail`); `di/F2` (printed server snippet does in-place overwrite, contradicting docstring's "no live swap"); `di/F3` (interrupted zstd → mtime check skips re-compress next run → ships corrupt with matching sha256); `di/F4` (no WAL checkpoint before compress — latent today); `di/F5` (`--skip-compress` ships stale `.zst` with no warning).

- **~15 P2s + ~10 P3s** — guardrail gaps, doc accuracy, hardening. Notable: `764/F1+N1` is a pattern, not a one-off — `__post_init__` validators bypassed by direct CLI override for `oracle_k, batch_size, target_oracle_agreement`; single `config.__post_init__()` call after the override block covers all three (strictly better than per-field re-validate).

**Both deploy-integrity hunt-claimed P0s demoted to P1 by cross-val** — real bugs, but the *success path* works and the script does not auto-execute the destructive command; **no P0 outside `767/F1`**.

Synthesized into `tasks/TASK_771_CHAIN_BUGFIX.md` — severity ledger, exact fix per finding, smoke discipline, 7-batch execution plan ordered by priority (P0 first as its own commit, then sync-db.sh P1s batched, then 767/F2 mctx, then 764/769 P2 batches, then SPEC doc refresh, then sync-db.sh further hardening).

- `l2_distance()` - Euclidean distance

- `compute_loss_barrier()` - Full barrier along path

- `policy_kl_divergence()` - KL between policies
- `jensen_shannon_divergence()` - Symmetric JS divergence

### e-dojo_v1.py Features
- **DojoConfig**: Configurable thresholds, intervals, directories
- **DojoState**: Persistent state with merge history
- **EasyDojo**: Main orchestrator class

  - Automatic interval adjustment (1.5x if safe, 0.75x if diverging)
  - Signal handling for graceful shutdown

## TASK_669: System Freeze Investigation (Evening Session)

### Incident
Overnight dual-branch training (started ~21:00) froze the system around 02:50. Symptoms:
- Blinking cursor on all TTYs
- Keyboard responsive but no input accepted
- No kernel panic message
- Required hard reboot

### Investigation Findings

**Memory Timeline (sar -r):**
```
21:00  →  27.9 GB free, 13% used
01:30  →  10.6 GB free, 25% used
02:40  →  0.86 GB free, 29% used  ← CRITICAL
02:50  →  FREEZE
```

**Root Cause: Memory leak in e-dojo merge operations**

1. `check_and_merge()` loads 336MB per cycle (2 × 168MB checkpoints)
2. No `gc.collect()`, no `del` statements, no `jax.clear_caches()`
3. Every merge retains ~600MB that never gets freed
4. Kernel cache grew 12GB → 31GB from checkpoint I/O
5. System OOM'd before OOM killer could act

**Merge events before crash:**
- Merge #1: 02:07:18
- Merge #2: 02:32:50
- Memory collapsed immediately after merges

### Training Progress Before Crash

Training was running fine - last log entry:
```
2026-02-06 02:50:29 - Epoch 101 Step 400/400 | Loss: 4.0262 | Agree: 7.9%
```

No errors, no warnings - just sudden death from OOM.

### Fix Applied

Changes to `e-dojo_v1.py`:

1. Added `gc` and `shutil` imports
2. `check_and_merge()` restructured with try/finally:
   - Del statements for all large objects
   - `jax.clear_caches()` + `gc.collect()` in finally
   - `shutil.copy2()` instead of double `save_checkpoint()`
3. `_perform_merge()` cleanup for Fisher arrays

**Status: FIXED**

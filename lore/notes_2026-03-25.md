## Session 38 — TASK_714 + TASK_715: Pipeline Overhaul

### Critical Discovery: Oracle Inconsistency (TASK_714)

The Foxglove data pipeline was computing oracle on 489-timestamp CHUNKS instead of the full period. Overlapping chunks gave contradictory targets for the same timestamp — the model saw conflicting labels for identical market states. This likely explains most of the train→benchmark gap (75% agree in training, 12-33% in benchmark).

**Fix**: Precompute oracle once on the full 258k-timestamp period when loading a segment. Store `oracle_selections`, `oracle_cum_pnl`, `returns` in slot dict. Training indexes into precomputed data instead of recomputing per-chunk.

### Critical Discovery: 96% Overhead (TASK_715)

After TASK_714 fixed oracle consistency, profiling showed:
- AR rollout: 55% of epoch time (2040 episodes × 0.5s sequential lax.scan)
- Encoding: 33% (2040 episodes × 0.3s jit_batch_encode_temporal)
- I/O: 8% (segment loads)
- **Actual training: 4%**

Root cause: buffer/episode architecture designed for cheap synthetic data applied to expensive historical episodes. Each 400-step episode built from scratch (encode + AR rollout), sampled 10 times, then discarded. 2040 episodes per epoch.

### TASK_715: Direct-Sample Pipeline — DONE

Bypasses the episode/buffer abstraction entirely for historical data:

**Precomputation at slot load time:**
- Oracle selections + cumulative PnL (TASK_714)
- State channels via `build_state_channels` on full period (float16, ~200MB/slot)
- Policy targets via `optimal_path_to_policy` on full period (float16, ~165MB/slot)
- Confidence = max softmax per asset (float16, ~32MB/slot)
- Total precomp: ~400MB/slot, ~6.8GB for 17 slots

**Per training step (`generate_batch_direct`):**
1. Sample 1024 positions via `pool.sample_positions()` (round-robin, stride-1, temporal jitter)
2. Group by slot, encode minimal price slices (~3MB not 330MB)
3. Index into precomputed targets/state/confidence (numpy index, ~0s)
4. Return batch — same format as before, trainer unchanged

**5% AR hybrid:** Occasional full AR episodes via `_build_historical_episode` to maintain state-awareness training signal. Configurable via `ar_direct_fraction`.

### Agreement Drop: 91% → 82-84%

Expected. The model was trained at 91% agreement with per-chunk oracle (inconsistent targets). Now seeing FULL-PERIOD oracle (consistent targets that match benchmark). The agreement dropped because:

1. Full-period oracle produces different targets than chunk oracle at many timestamps
2. The model's learned patterns partially match the old (wrong) targets
3. It needs to re-learn on the correct targets

This is **good** — the model is now being corrected. Agreement should climb back as it adapts to consistent targets. The key metric to watch is BENCHMARK agree_trade, not training agreement.

### Bug Fix: Index Out of Bounds on Slot Rotation

`generate_batch_direct` crashed when `sample_positions` returned cursors from a pre-rotation slot that was replaced by a shorter segment. Fix: clamp decision indices against actual slot array size, drop invalid cursors.

### Short Segments Still Cause Rotations

P10 (49 days, 71k ts), P11 (37 days, 53k ts), P13 (40 days, 57k ts) still rotate frequently because their cursors exhaust in ~53k steps while long segments last ~258k. Each rotation = ~45s. With direct sampling consuming 1024 cursors per step across 17 slots, short slots get ~60 cursors per step and exhaust in ~880 steps (~2 epochs). Long slots last ~4300 steps (~11 epochs).

This is much better than before (was rotating 3-5 times per epoch), but short segment I/O still dominates epoch time when it hits. Future improvement: keep short segments in memory permanently (cursor reset, no reload).

### Val MSE: 153k-165k

The val MSE jumped from ~291 to ~153k. This is because remaining PnL is now computed from the FULL period oracle (258k steps of cumulative PnL) instead of 400-step episodes. The value head was trained on 400-step remaining PnL (range 0-5) and now sees 258k-step remaining PnL (range 0-100+). This is the same metric-scale mismatch found in the benchmark audit — not a real regression.

### Bug Fix: Encoder Slice Out of Bounds

Second crash in `generate_batch_direct`: `jax.lax.dynamic_slice` got a price array shorter than `ws=64`. Cause: `c_max + ws` exceeded `slot['hm'].cache_data` length after slot rotation to a shorter segment. Cursors from the old (longer) slot were applied to the new (shorter) slot.

Fix: moved bounds validation BEFORE encoding. Cursors now checked against both `T_prices - ws` and `T_ret - ws`. Invalid cursors dropped before any JAX operation. Combined with the earlier decision-index guard into a single upfront filter.

### Two Edge Cases from Slot Rotation

Both crashes (IndexError on `policy_targets`, TypeError on `dynamic_slice`) had the same root cause: `sample_positions()` collects cursors, a rotation replaces the slot with a shorter segment mid-collection, and `generate_batch_direct()` applies old cursors to the new slot.

The fix is defensive: validate all cursors against the CURRENT slot's actual array sizes before any indexing or encoding. This is robust regardless of when rotations happen.

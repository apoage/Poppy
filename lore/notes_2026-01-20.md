## TASK_105: Dojo V3 Period Wraparound & Defensive Loading

### The Problem

Dojo v3 historical training was hanging at Batch 5:
```
2026-01-19 13:54:04 - BATCH 5: Periods 17-17
                      P0: 2025-02-25 → 2025-11-30 (278 days)
<hangs forever>
```

Period 17 requested data beyond what exists in the database. The data loader waited indefinitely instead of failing.

### Root Cause Analysis

1. `training_schedule.json` contains 17 periods spanning 2018-10-17 to 2025-11-30
2. Database has continuous data only up to ~March 2025
3. Sparse data point on 2025-12-12 (from a test download) made `MAX(timestamp)` misleading
4. No validation - loader just hangs on missing data

### Solution: Defense in Depth

**1. Fail-fast in data loader** (`mcts_trader/data/history.py`):
```python
if self.filter_start_ts > self.max_time:
    raise ValueError(f"Requested start_date beyond database max")
```

**2. Config override for effective end date** (`config/dojo_override.json`):
```json
"db_effective_end_date": "2025-03-15"
```

**3. Filter periods at startup** (`dojo_v3_historical.py`):
- `_get_db_max_date()` - checks config override first, then queries DB
- `_filter_valid_periods()` - removes periods where END date > db_max_date

**4. Two training modes**:
- `--stratified` (default): One-shot through all valid periods, then stop
- `--stratified --loop`: Infinite cycle until Ctrl+C

### Files Modified

- `mcts_trader/data/history.py` - Added bounds check (fail fast)
- `tools/orchestration/dojo_v3_historical.py`:
  - Added `_get_db_max_date()` with config override support
  - Added `_filter_valid_periods()` checking END date
  - Added `--loop` CLI flag
  - Refactored `run_training_stratified()` for cursor-based iteration

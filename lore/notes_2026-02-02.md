# Session Notes - 2026-02-02

## TASK_136: BC Training Bottleneck Fix - 24× Speedup

### Problem

```
Train time: 144s/epoch (should be ~10s)
GPU utilization: 5-17% (should be 80%+)
Root cause: BC encoding runs 50× per epoch, ~2.5s each
```

### Solutions Implemented

#### TASK_136d: Reduce BC Frequency (1 line change)
- Added `bc_frequency: int = 5` to `ExpertBCConfig`
- BC now runs every 5 iterations instead of every 1
- **Effect**: 50 BC calls → 10 per epoch

#### TASK_136a: Pre-encode with Compression (main optimization)

| Metric | Before | After |
|--------|--------|-------|
| Obs shape | (27, 64, 64) | (27, 64) |
| Per demo | 432 KB | 6.8 KB |
| Compression | - | **64×** |
| Encoding | At sample time | At add time |

**Key insight**: ALL 27 encoder channels use `jnp.tile()` - 100% redundancy.

**Files modified**:
1. `mcts_trader/env/jax_encoder.py`
   - `_compute_all_channels_compressed()` - returns (27, n) not (27, n, n)
   - `encode_observation_compressed()` - wrapper
   - `jit_batch_encode_compressed()` - batch encoding
   - `jit_batch_tile_compressed()` - expand at sample time

2. `mcts_trader/jax_agent/expert_buffer.py`
   - `_compressed_obs: Dict[int, np.ndarray]` - storage
   - `preencode_episode()` - batch-encode all steps at add time
   - Modified `_encode_observations_vectorized()` to use compressed obs

3. `train_jax_fast.py`
   - Added `preencode_episode()` call after `add_episode()`

### Results

| Epoch | Before | After |
|-------|--------|-------|
| 1 (warmup) | ~144s | 48s |
| 2+ | ~40s | **~6s** |

**Training speedup: ~24×** after warmup.

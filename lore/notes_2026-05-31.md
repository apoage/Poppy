### Why everything's been null — the reframe
A codebase survey (three parallel readers over Poppy / Foxglove / this cycle) produced the unifying
insight: **the trading objective was never in the loss, and the real planning loop was never turned
on.** Stage-B's loss is policy-CE-vs-MCTS-visits + value-MSE-vs-oracle-PnL + BC — none is a realized
-PnL gradient. The net is trained to *classify* (match an oracle) and *measured* on *trading*; the
gap between those is exactly where 14 experiments died (the classifier-alpha anti-correlation, the
trade-rate explosion). Meanwhile `train_jax_fast.py` holds the real MuZero Expert-Iteration loop —
search→targets→train→re-search — and it **hasn't run since ~May 2025.** The whole campaign optimized
the supervised *seed* of a loop that's been switched off.

### Three branches, scoped and launched
- **A — PnL-in-loss** (`exp/A-pnl-in-loss`, TASK_787). A default-OFF flag adds an over-trade penalty
  to the Stage-B loss. Built by a campaign-shipper sub-agent, **bit-identical when OFF** (grad_norm
  and all 70 param leaves equal to the pre-change graph — the penalty is gated at trace time, not
  masked). Launched on the server paired vs 760 a1b1: w=0.1 chain (G2, with a w=0.0 reproduction
  cell to kill the cross-campaign confound that burned 746) and a w=0.2 dose-response arm (G1).
- **B — Poppy ExIt revival** (`exp/B-poppy-exit-loop`, TASK_788). The headline. A general-purpose
  agent found the dormant loop has **no logic bit-rot** — the only blocker was VCS staleness (the
  entire live Poppy stack is uncommitted: ~25 untracked modules + ~29 modified-uncommitted, so a
  clean checkout is broken; the server only runs because deploy rsyncs the dirty tree). It booted
  cold-start synthetic and **ran 100/100 epochs on the server without collapsing** — loss flat ~12.5,
  unlike the 780 bridge. *The loop is alive and stable.* That de-risks B; the real version
  (warm-start a1b1 + regret-weighted replay + sims-scaling) needs a pkl→Orbax adapter, not built.
- **C — Temporal token middle-layer** (TASK_789). The operator's idea: tokenize OHLC shapes into a
  vocabulary, train a sequence world-model, let MCTS plan over it. A background research pass
  reshaped it: **don't quantize raw price** (Chronos did exactly that and its own authors walked it
  back in Chronos-2). The robust stack is **RevIN→patch→FSQ→Δ-IRIS GPT→stochastic-MCTS-over-tokens**
  — and that last piece is literally "Vector Quantized Models for Planning" (DeepMind 2021), MuZero
  -with-VQ. The operator's "robust tokeniser" worry maps to a precise fix: FSQ is collapse-proof by
  construction; RevIN kills scale/regime brittleness. Two design forks resolved by the operator:
  **late mixing** (per-asset tokens, cross-asset attention at the decision head over token
  embeddings — preserving the load-bearing cross-sectional signal that TASK_738 proved worth +18pp)
  and **frozen-vocab-first**. Honest caveat from the candlestick literature: shape signal is weak
  after costs, so C0 is a ½-day kill-switch (does token edge beat a returns-shuffled control OOS).

### The crash — and the discipline it forced
Launching C0's FSQ build on the workstation's **single display-driving 3090** **hard-locked the
whole machine** (~22:11). The operator's two guesses were both wrong, and the forensics are clean:
**not OOM** (45 GB RAM, 128 GB swap unused, zero oom-killer entries) and **not CPU** (no MCE,
thermal, lockup, or panic) — the kernel log simply **dead-stopped**, the signature of a too-fast-to
-log GPU driver hang, with the last lines being Firefox WebGL on the NVIDIA device coincident with
JAX grabbing the same GPU. The server experiments were untouched (separate box, tmux — the discipline
paying off again).

Two durable fixes, not just a "be careful":
- **`tools/safe_run.sh`** — every job runs in a `systemd-run --user` cgroup scope with
  `MemoryMax`/`MemorySwapMax=0`, so a runaway is OOM-killed **in its own cgroup, never the host**.
  Verified live: a 4 GB allocation under a 1 GB cap was killed, the shell and host survived. `--cpu`
  keeps compute off the display GPU. Works on workstation and server. The general answer to the
  operator's instinct: *encapsulate properly so OOM can't happen — and it applies to the server too.*
- Memory `feedback_no_gpu_jobs_on_workstation`: GPU compute → server only; CPU-only probes OK on the
  workstation; encapsulate via safe_run.

The C0 harness was salvaged (`adf8c15`) — the dead agent had even pre-built a numpy/CPU fallback as
it fought the GPU path in its last minutes.

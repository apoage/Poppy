- `mcts_trader/jax_agent/__init__.py` +2 LoC — exports.
- `phase2_config.py` +12 LoC — `oracle_mode: str = "topk_path"` (default, byte-identical), `sign_epsilon: float = 1e-4`, comment documenting reserved `hybrid` mode.
- `train_phase2.py` +28 LoC — CLI flags `--oracle-mode {topk_path,dense_sign,hybrid}` and `--sign-epsilon`. `hybrid` raises `NotImplementedError` at startup (reserved).
- `train_easy.py::SegmentPool._make_slot` +23 LoC — replaces `policy_targets_full` with dense-sign output when `oracle_mode=="dense_sign"`. `oracle_selections` / `oracle_cum_pnl` untouched (value + path remain top-k).
- `tools/run_739_dense_sign.sh` (NEW, 116 LoC) — one training + one benchmark → `task_739_result.md`.

**Key implementation decisions:**
- Operates on log-returns, not prices (matches `path_solver.py` convention).
- `r_fwd = sum(returns[t : t+lookahead])` per step.
- Boundary invariant: last `lookahead-1` rows forced HOLD (the `t = T-lookahead` row has a full window and is valid).
- Action encoding: project convention `{0=SELL, 1=HOLD, 2=BUY, 3=LSELL, 4=LBUY}`. Dense-sign never emits limit actions.
- Injection at precompute (SegmentPool) not batch-time — matches TASK_729c-era pattern, minimal surgical change.

**ε calibration caveat (flagged by smoke test):** on synthetic vol=0.01/step, ε=1e-4 gave ~90% trade density (46.6% SELL / 9.8% HOLD / 43.7% BUY). Real minute-bar crypto has vol ~0.001–0.003/step → 20-step cum std ~0.004–0.013; ε=1e-4 will likely produce similar ~90% trade density — outside the 5–15% target the spec specifies. **First real run is primarily a wiring check; ε may need bumping to 5e-3 to 1e-2** based on early epoch label distribution.

**Backward compat verified:** `oracle_mode=topk_path` default → byte-identical to pre-739.

- `train_phase2.py` +~90 LoC — CLI flags, config plumb, pipeline field, loss integration, metrics, CSV columns, log line.
- `train_easy.py` +~65 LoC — `_load_bella_shard` + slot field + oracle_cfg routing.

**Correction to spec's checkpoint path:** The spec pointed to `jax_ckpt_easy_*/branch_*_bella/phase1_best.pkl` for Bella. Those are actually **MuZero-agent checkpoints trained on Bella data** (keys: `trm`, `action_embedding`, `dynamics_*`), NOT generators. The real Bella generator is the Orbax checkpoint at `/home/lukas/Trader/checkpoints/diff_teacher/generator_best/generator/` (Jan 25, 2026). Agent discovered this by inspecting pickle keys and corrected the implementation to use the correct path.

**Key implementation decisions:**
- Prediction space: **log-returns** (scale-stable across assets; matches `aux_price_head` so loss landscape is comparable).
- K=4 samples per window, averaged.
- Horizons `(1, 5, 10, 20)`.
- Per-window **regime estimation** (mean/std of observed window's log-returns), NOT prefix inpainting — Bella's conv-flow arch does not support clean prefix conditioning.
- Missing-shard semantics: NaN sentinel in target + per-cell validity mask in loss → samples from unregistered periods contribute zero gradient. `bella_valid_frac` tracked as a metric.
- Manifest: `config/bella_preds_manifest.json`. Shards: `data/bella_preds/bella_preds_<start>__<end>.npz`.

**Known limitation:** per-window regime estimation is a crude proxy for true window-conditional forecasting. Within a period, all windows sharing the same regime bucket get the same target (modulo K=4 sample noise). If β-v2 doesn't break the ceiling, the natural next step is Bella retrain with window-prefix conditioning (out of scope, would be a new Bella training task).

**Dry-run verified against the real Bella checkpoint**: wall=4.9 s, preds shape (4, 64, 4), values in ~1e-2 log-return scale.

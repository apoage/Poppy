## Session 50 — TASK_721: AsyncBatchPipeline

### What Was Done

Replaced `ConsecutivePairGenerator` + `PrefetchGenerator` in `train_phase2.py` with `AsyncBatchPipeline` — a two-phase pipeline splitting numpy (background thread) from JAX (main thread).

**Key changes:**
1. **Thread-safe split**: `_prepare_numpy()` on background thread (pure numpy), `_encode_jax()` on main thread (JAX GPU)
2. **Random sampling**: uniform random positions within slots (round-robin across slots for balance), replacing sequential cursor with stride=1
3. **Vectorized n-step rewards**: single numpy broadcast `(n, N)` instead of Python `for k in range(nstep)` loop
4. **Per-sample window extraction**: each sample gets a compact `(ws+nstep, n_assets, 5)` window, all flattened into one array for 3 encoder calls total

### Critical Bug Found & Fixed

First version had a **gen time regression**: 5617s/epoch (vs old 41s). Root cause: random sampling spread cursors across full slot range, so `price_slice = cache[c_min:c_max+84]` copied ~258k timesteps per slot to GPU — 17 slots x 3 encoder calls = 51 massive GPU transfers per step.

**Fix**: extract per-sample windows in numpy, flatten into `(B*win_len, n_assets, 5)`, use stride offsets for 3 total encoder calls.

| Metric | Broken (v1) | Fixed (v2) |
|--------|-------------|------------|
| Encoder calls/step | 51 | 3 |
| GPU transfer/step | ~170 MB | 27.5 MB |
| Peak RAM/step | ~22.5 GB | 27.5 MB |
| `_encode_jax` warm | ~14s | ~2ms (CPU) |

### Causality Analysis

Random sampling is causality-coherent for Phase 2:
- Within each sample: `obs_t → obs_t1 → obs_tN` temporal ordering preserved
- Model input only sees past data up to decision point
- Dynamics consistency loss trains on individual transitions — doesn't need cross-batch ordering
- TRM has no recurrent hidden state carried across training steps
- i.i.d. sampling is actually better for SGD (independent gradients vs 75% overlap)

### TASK_722 Drafted: Bella-Conditioned Rollouts for MCTS

Design brainstorm → task spec for using Bella as MCTS world model:

**Architecture**: Bella = imagination, Dynamics MLP = grounding
- Bella observes current market state → generates K=8 plausible futures via flow matching
- Dynamics MLP scores each branch by consistency (predicted vs actual encoded latent)
- MCTS searches over Bella futures, weighted by consistency + value
- Branches where Bella hallucinated get deprioritized by low consistency scores

**Key design decisions:**
- Conditioning via skeleton extraction from observed window (reuses Bella's trained FiLM path, no new params)
- Inpainting during ODE integration to anchor generation to reality
- Action-independence is correct: markets don't care about our trades at this scale. MLP handles action-dependence.
- Virtuous cycle: Bella teaches dynamics (better transitions) → dynamics filters Bella (reject hallucinations) → MCTS improves → policy improves

**VRAM**: ~2.5GB combined (fp32) vs 24GB available. int8 quantization feasible as fallback but unnecessary.

### Oracle Value Saturation — DIAGNOSED & FIXED

First oracle value run (session 45, late) hit same saturation: `td_mean=10.00, td_std=0.00, value_loss=0.000`.

**Root cause**: `remaining_pnl = oracle_cum_pnl[-1] - oracle_cum_pnl[t]` computed remaining PnL to the **end of the entire 258k-step segment**. Total cumulative PnL ~258 raw, ×2.0 value_scale = 516 → clips to 10 for every sample.

Phase 1 doesn't have this issue because it computes remaining PnL within short episodes (few hundred steps).

**Fix**: Fixed-horizon oracle values:
```python
horizon = config.oracle_value_horizon  # 400 steps, matches episode length
end_indices = np.minimum(decision_indices + horizon, len(oracle_cum_pnl) - 1)
remaining_pnl = oracle_cum_pnl[end_indices] - oracle_cum_pnl[decision_indices]
```

Gives returns in ~0-5 raw range → 0-10 scaled. Same range Phase 1 sees.

Added `oracle_value_horizon: int = 400` to Phase2Config.

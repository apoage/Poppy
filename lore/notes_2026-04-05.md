### TASK_718a-d: PopArt + Reward Fix — Initial Run FAILED

Launched Stage B with 718a-d changes (reward scaling fix + PopArt normalization).

**Result: Same stall pattern.** Value head oscillated between two saturated modes:
- **Mode A**: td_mean ≈ -9.8, value_loss=0.000, policy≈1.38
- **Mode B**: td_mean ≈ +9.95, value_loss=0.000, policy≈3.5

Ran 229 epochs before killed. PopArt tracked statistics but couldn't fix the core issue.

**Root cause diagnosis — two additional issues beyond 718:**

**1. Value head saturated from Phase 1**
- Phase 1 trained on `oracle_returns * 2.0` → V(s) ≈ 10 for all states
- TD(0) bootstrap: `td = r + 0.997 * V(s_next) ≈ 0.1 + 9.97 = 10.07` → clips to 10
- Self-reinforcing: V predicts 10 → target is 10 → value_loss=0 → no gradient

**2. γ=0.997 makes true discounted returns exceed support range**
- Per-step reward ≈ 0.1 (PnL × REWARD_SCALE)
- True V = r/(1-γ) = 0.1/0.003 ≈ 33 — way outside [-10, 10] support
- Everything clips to boundary → saturation inevitable

### Two Additional Fixes Applied (value head reset + td_discount)

**Fix 1: Reset value head at Stage B start** (`reset_value_head=True`)
- He-init all 3 value head layers (`value_head_1/2/3` in `reasoning/`)
- V(s) starts near 0 instead of saturated at 10

**Fix 2: Separate TD discount** (`td_discount=0.95`)
- Lower than `mcts_discount=0.997` (MCTS still uses 0.997 for planning)
- True V ≈ 0.1/0.05 = 2.0 — comfortably in [-10, 10] support range

### TASK_719 Step A: Oracle Value Targets — IMPLEMENTED

Added `value_target_mode` config field (default="oracle"). When enabled:
- `generate_batch()` computes `remaining_pnl = oracle_cum_pnl[-1] - oracle_cum_pnl[t]` per sample
- Value loss uses `oracle_values * value_scale(2.0)` instead of TD(0) bootstrap
- PopArt normalizes oracle values same as TD targets
- Branch resolved at closure time (Python bool), no JIT recompilation

This is the same value signal that Phase 1 uses successfully. The hypothesis: if MCTS gets a discriminating value function, it can produce policy targets that actually improve the policy. The model can't achieve oracle returns, but the *relative ordering* of states is what MCTS needs.

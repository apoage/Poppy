## Session 32 — TASK_708: MSE-Based AR Feedback

### Issue: 0% Trade Rate with AR=1.0

With AR blend at 100%, the model feeds its own value predictions back as state input. But the value head is catastrophically miscalibrated (benchmark MSE ~1160, target <0.1). This creates a vicious cycle:

1. Bad value predictions → bad state channels fed to model
2. Bad state input → model can't learn to trade → HOLD everything
3. 0% trade rate → no learning signal from actual trades

Training agreement ~82% but model is pure HOLD. Benchmark shows 0.0% trade rate across all 6 periods.

### TASK_708: MSE-Based AR Feedback — DONE

**Design**: Reactive MSE→AR feedback using EMA-smoothed validation MSE to dynamically set `config.ar_max_blend`. When value head is uncalibrated, give more oracle state guidance. As it calibrates, let the model earn self-prediction rights.

**Mapping (log-scale interpolation):**
- MSE ≤ 0.1 → AR = 1.0 (value head calibrated, full self-play)
- MSE = 1.0 → AR = 0.6 (getting there)
- MSE ≥ 10.0 → AR = 0.2 (floor — heavy oracle guidance)

**EMA smoothing**: α=0.1 (~10-epoch window) prevents epoch-to-epoch whiplash from period cycling (val MSE oscillates 0.05↔11.0 across periods).

**Changes in `train_easy.py`:**
- `import math` added
- EMA state init before training loop: `mse_ema=1.0`, `AR_FLOOR=0.2`, `AR_MSE_GOOD=0.1`, `AR_MSE_BAD=10.0`
- After validation: update EMA (skip NaN/inf), log-scale interpolation → `config.ar_max_blend`
- Epoch log line now includes `AR: 60%`
- CSV columns added: `ar_blend`, `mse_ema`

No JIT recompilation — `ar_max_blend` is read per-episode in Python, not a JIT static arg.

1. **AR feedback settled lower than expected** — task predicted 40-60%, actual is 33-37%. The alternating MSE (0.05 / 9-11) pushes EMA higher, keeping AR near floor. This is actually correct behavior — value head is genuinely uncalibrated on half the periods.

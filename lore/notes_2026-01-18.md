### 2. Asset Padding Fix

**Problem:** Model trained on 64 assets (320 actions), but first historical period only has 61 assets (305 actions) → shape mismatch error.

**Fix:** `dojo_v3_historical.py` now pads asset lists to 64 by repeating assets cyclically:
```python
# Pad to 64 assets if needed (model trained on 64 assets)
N_ASSETS = 64
if len(assets) < N_ASSETS:
    while len(assets) < N_ASSETS:
        assets = assets + assets[:N_ASSETS - len(assets)]
```

### 3. MCTS Sims Warmup Disabled

**Problem:** Each 60-epoch run was wasting ~5 epochs on sims warmup (8→24 sims). With 243 runs = ~1,200 wasted epochs.

**Fix:** Set `--sims-warmup 0`, `--sims-min 24` for historical training. Model already trained on L0-L14 synthetic, no warmup needed.

### 4. Fixed Epochs Per Run

**Problem:** Epochs per run was calculated from period duration (180 days / 15 = 12 epochs). Too short for proper training.

**Fix:** Always use 60 epochs per run (one full block = one benchmark):
```python
epochs_per_run = self.epochs_per_block  # 60
```

### 5. Adaptive Fees System

Created `mcts_trader/jax_agent/adaptive_fees.py` - gradual fee/slippage introduction based on reward performance.

**Fee Stages:**
| Stage | Fee (bps) | Slippage (bps) | Trigger |
|-------|-----------|----------------|---------|
| 0 | 0 | 0 | Start |
| 1 | 8 | 2 | Reward EMA > 2.5 for 10 epochs |
| 2 | 16 | 5 | Reward EMA > 2.5 for 10 more epochs |

**New CLI flags:**
```bash
--adaptive-fees                    # Enable adaptive fees
--fee-reward-threshold 2.5         # Reward threshold for upgrade
--fee-upgrade-epochs 10            # Consecutive epochs above threshold
```

**Integration:**
- `VectorBTTradingEnv.set_fees()` method for dynamic fee updates
- CSV logging: `adaptive_fees`, `fee_stage`, `fee_bps`, `slippage_bps`, `fee_reward_ema`
- Controller updates env fees when stage changes

### Key Finding: Fisher Merging is Destructive
Fisher merging destroyed model weights. The "Squisher shortcut" (using Adam's v as Fisher) may be:
1. Producing noisy estimates
2. Letting Bella's higher variance dominate L0's lower variance
3. Not suitable for this use case

## Root Cause Analysis

### Oracle Distribution (Both Identical)
```
L0 Synth: SELL=3.1%, HOLD=93.8%, BUY=3.1%
Bella:    SELL=2.3%, HOLD=93.9%, BUY=3.8%
```
Both target ~94% HOLD, so action distribution is NOT the issue.

### Early Training (Synth Was Ahead!)
```
Merge 1: A=2.9%, B=4.3%  (B ahead)
Merge 2: A=3.3%, B=4.4%  (B ahead)
Merge 3: A=3.5%, B=4.5%  (B ahead)
```
L0 started ahead, then Fisher merging killed it.

### Theory: Fragile vs Robust Representations
- L0 sine waves → specific, fragile weight patterns
- Bella diverse patterns → distributed, robust representations
- Fisher merging destroyed the fragile L0 patterns

## Fixes Implemented

### 1. Divergence Brake (cos < 0.85)
Instead of emergency merge when branches diverge too much:
- Restart the worse-performing branch from last merged checkpoint
- Don't count as a merge
- Prevents "averaging into mush"

### 2. TIES Merging (cos 0.85-0.95)
For moderate divergence, use TIES instead of Fisher:
- Trims small delta values
- Elects sign by majority vote
- Only keeps updates matching elected sign
- Resolves sign conflicts that cause damage

### 3. Fisher Normalization
Added `normalize_fisher()` before merge:
- Normalizes each Fisher tree to sum=1
- Prevents one branch dominating due to higher variance
- Fisher now safe to use in late phase

### 4. Longer Merge Intervals
```python
min_steps_between_merge: 8000   # Was 4000 (10 epochs → 20 epochs)
max_steps_between_merge: 20000  # Was 16000
initial_merge_interval:  12000  # Was 8000
```
Gives branches more time to "harden" before merge exposure.

## New Merge Strategy

```
cos > 0.95:     FedAvg (safe, early phase)
cos 0.90-0.95:  TIES (resolves sign conflicts)
cos 0.85-0.90:  Fisher normalized (importance weighted)
cos < 0.85:     BRAKE - restart worse branch, skip merge
```

## Dual-Bella Experiment Setup

### Problem
- Bella vs Synth L0 has distribution mismatch
- Synth learns 3.5x slower (5% vs 18%)
- 94% HOLD is too conservative (only 6% trades)

### Solution: Dual-Bella with Inversion
Both branches use Bella but with opposite market directions:
- Branch A: Normal Bella (bull = bull)
- Branch B: Inverted Bella (bull → bear, bear → bull)

This provides:
- Same distribution → clean merges
- Diverse market exposure → robust features
- Aligned learning speed

### Changes Made

#### 1. Oracle Less Conservative (easy_config.py)
```python
oracle_k: int = 10  # Was 4 → gives ~84% HOLD instead of 94%
```

#### 2. Return Inversion (train_easy.py)
```python
# In config
invert_returns: bool = False  # True for inverted branch

# In training loop
if getattr(self.config, 'invert_returns', False):
    log_returns = -log_returns  # Bull → Bear
```
Added `--invert-returns` CLI flag.

#### 3. e-dojo Dual-Bella Mode (e-dojo_v1.py)
```bash
# New flag: --dual-bella
python e-dojo_v1.py --run --preset large --epochs 2500 --dual-bella
```

Changes:
- Added `invert_returns` param to `launch_branch()`
- Added `dual_bella` param to `launch_dual_branches()`
- Branch B name changes to "branch_B_bella_inv" in dual-bella mode
- Updated divergence brake to handle both branch types

### Launch Command
```bash

rm -rf jax_ckpt_easy_A jax_ckpt_easy_B jax_ckpt_easy_merged
```

### Expected Behavior
- Both branches should learn at similar rates (unlike Synth lag)
- Cosine should stay high (~0.97+) due to aligned distributions
- Merges should be FedAvg (early phase, cos > 0.95)
- Oracle agreement should grow faster with 16% trade actions vs 6%

### Bug Fix
`restart_both_with_checkpoint()` was hardcoded to look for `branch_B_synth` key.
Fixed to detect `branch_B_bella_inv` when in dual-bella mode.

### Rationale
Crossing Bella with Bella (inverted) instead of Synth with Synth makes more sense:
- Same generator → same distribution → compatible representations
- Inversion provides diversity without distribution mismatch
- Both branches see "real-looking" markets, just opposite directions
- Should merge cleanly since internal features are aligned

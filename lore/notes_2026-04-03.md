### Bugs Found and Fixed

**1. `optax.masked` does NOT zero frozen gradients — it passes them through**

This was the session's biggest finding. `optax.masked(inner, mask)` with `mask=False` means "don't apply the inner transform" — but the raw gradient is still returned as the update! This caused catastrophic divergence: the encoder was receiving unclipped raw gradients (grad_norm=383 on step 0), and by step 1 the consistency loss exploded to 1.5M.

**Symptoms**: E0 looked reasonable, E1+ diverged catastrophically with consistency loss → millions, grad_norm → tens of thousands. Encoder latent std jumped from 4.2 to 2600+.

**Fix**: Switched all three optimizer factories to `optax.multi_transform`:
```python
optimizer = optax.multi_transform(
    {'train': optax.chain(clip, adamw), 'freeze': optax.set_to_zero()},
    labels,  # 'train' or 'freeze' per leaf
)
```
This properly zeros updates for frozen params. Fixed in:
- `create_dynamics_optimizer()` (Stage A — wasn't causing visible issues due to stop_gradient)
- `create_stage_b_optimizer()` (Stage B — was the root cause of divergence)
- `create_stage_b_optimizer_with_encoder()` (encoder unfreeze)

**Verification**: After fix, encoder max diff = 0.0 after train step.

**2. Self-referential value loss (MCTS root_value = own prediction)**

The spec said to use MCTS root_value as value target: `value_loss = CE(value_logits, scalar_to_categorical(root_value))`. But root_value comes from `_categorical_to_scalar(model.value(obs))` — the model's OWN value prediction. So the loss is `CE(value_head(obs), value_head(obs))` ≈ 0 trivially. This gives no learning signal, and as params update, small perturbations cause oscillating self-predictions.

**Symptoms**: value_loss = 0.0 on E0 (perfect self-prediction), then wild swings (1845, 2055, 0, 0...).

**Fix**: TD(0) bootstrap — `v_target = r_step + γ * V(s_next)`. Uses actual per-step reward plus discounted next-state value (from stopped-gradient forward pass on obs_t1). This provides real learning signal from environment feedback.

**3. Oracle targets are per-asset softmaxed (not globally normalized)**

`optimal_path_to_policy()` returns (T, 320) where each group of 5 actions per asset is independently softmaxed. Total sums to 64, not 1.0. Using global `softmax_cross_entropy` would be incorrect.

**Fix**: BC loss reshapes to (B, 64, 5) and computes per-asset CE, matching Phase 1's `easy_trainer.py` pattern.

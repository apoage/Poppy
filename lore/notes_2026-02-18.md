## TASK_681: Oracle Trade Density Ceiling — RESOLVED (Phase 0)

### The Painful Truth

15 CRITs across 3 adversarial review rounds, 6 fix options (A-F), and the answer
was changing one number: `oracle_k: 1 → 4` in `easy_config.py`.

### Why It Took So Long

The k=1 density ceiling (1.56% trades on 64 assets) was masked by multiple
plausible alternative explanations. Each fix (TASK_674-680) addressed a real
issue but none could overcome the structural ceiling:

| Fix | What it fixed | Why it couldn't help |
|-----|--------------|---------------------|
| TASK_674 | 6 plateau bugs | Bugs were real but not the bottleneck |
| TASK_675 | Tech debt, gradient drowning | Equal gradients on sparse data = equal nothing |
| TASK_677 | Warmup disabled | Gradient timing doesn't create trade labels |
| TASK_679 | Threshold 0.001→0.0005 | Already near k=1 ceiling, threshold irrelevant |
| TASK_680 | Trade-biased sampling | Shows trade windows more but can't create new trades |

### The Fix

```python
# easy_config.py:54
oracle_k: int = 4  # Was 1. TASK_666 original design was k=4.
```

Trade density: 1.56% → ~6.25%. Per-class per-asset examples: 2-3 → 4-8 per batch.

### Historical Context

- TASK_666 designed k=4 from the start (`TASK_666_IMPLEMENTATION_PLAN.md:179`)
- TASK_143/145 reverted a failed k=10 experiment straight to k=1
- k=4 was never tested — it was skipped in the revert
- This fix is a restoration of the original design, not a new experiment

### Adversarial Review Summary (15 CRITs)

Round 1 (internal): CRITs 1-6 — cross-asset attention, MCTS coupling, density math
Round 2 (external): CRITs 7-11 — gradient starvation, value mismatch, curriculum sensitivity
Round 3 (TASK_666 context): CRITs 12-15 — k=4 was original design, k=10→k=1 skipped k=4

Final recommendation: **B (k=4) first**, then F (neg sampling) if needed, then D (hybrid) last resort.

### Value Head Concern (CRIT-8)

k=4 trains value on 4-asset PnL, inference uses k=1. Moderate overestimation
(2-4× vs k=10's 5-10×). Acceptable for now — value represents "market opportunity"
rather than "realizable single-trade PnL." Can scale by 1/k later if needed.

### What Was Built

`AssetTransformerEncoder`. Uses minGRU recurrence to preserve temporal ordering.

| | V2 (flatten) | V3 (minGRU) |
|---|---|---|

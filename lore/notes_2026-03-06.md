### TASK_698: Foxglove Historical Data Training — Full Rewrite

Validated the original spec against the actual codebase. Found the original design was wrong — it tried to integrate historical data directly into `OnTheFlyGenerator` instead of following the proven dojo_v3/v4 subprocess pattern.

**Rewrote 3 times** to get it right. Final spec:

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Data source integration | New branch in `_refill_buffer()` | Same pattern as Bella/synth, minimal code change |
| Period cycling | Orchestrator advances per block (one period per subprocess) | Avoids `switch_period()` which doesn't exist, avoids RAM cache reload |
| Benchmark timing | After each merge in e-dojo loop | Natural pause point, both GPUs idle |
| Benchmark tool | `benchmark_easy.py` (TASK_682) with `--json` | Already complete — 6 periods, balanced_acc, alpha, sharpe, drawdown, trade_rate |
| Shape | Close prices only `(T, n_assets)` | Matches existing pipeline. Full OHLCV deferred to TASK_703 |
| Asset padding | Cyclic repeat to 64, done by orchestrator | Copy dojo_v3 pattern |

Added data leakage analysis table + startup validation assertion.

### TASK_703: True OHLCV Pipeline — Created

During TASK_698 review, discovered the encoder fakes OHLCV:
- 8 of 27 channels (30%) carry zero real signal
- High = Low = Close, Volume = ones

Then discovered something worse: **Bella already generates full OHLCV `(batch, seq, 64, 5)` on GPU**. The output is thrown away at a single line (`setup.py:657`):
```python
close_prices = generated[:, :, :, 3]  # discards 80% of Bella's output
```

We've been paying the VRAM cost for 5-channel generation and using only 1 channel for 2500+ epochs.

TASK_703 spec covers:
- Phase A: Encoder accepts `(T, n_assets, 5)` with backward compat
- Phase B: Stop discarding Bella's OHLCV — fix inverse normalization for all 5 channels
- Phase C: Training pipeline `_generate_batch_episodes()` handles 3D
- Phase D: Historical returns full OHLCV from cache
- Phase E: Benchmark passes OHLCV to encoder
- Phase F: SyntheticMarket gets noise-based HLV wrapper

### Key Findings

1. **Bella OHLCV already exists** — trained on real OHLCV from DB, generates all 5 channels, discarded at consumer
2. **No VRAM increase** — computation already happens, just stop discarding
3. **30% encoder capacity wasted** — 8 channels are constant/duplicate
4. **Distribution mismatch risk** — if training uses fake OHLCV but real trading sees real OHLCV, model encounters unseen distributions at inference time

### Architecture

```
e-dojo (orchestrator, CPU-only)
├── Branch A (RTX 3090): train_easy.py --db-path ... --start-date ... --end-date ...
├── Branch B (CMP 90HX): train_easy.py --bella
├── Merge: Fisher-weighted checkpoint merge
├── Period advance: schedule_manager.advance() → next period loaded on restart
├── Block check: every N merges → save foxglove_H{N}.pkl + run benchmark_easy.py
└── Repeat
```

### Key Design Decisions

1. **Historical as new branch in `_refill_buffer()`** — same downstream pipeline as Bella/synth (oracle, encoder, buffer)
2. **One period per subprocess** — orchestrator advances, no mid-training period switching
3. **Schedule manager** — filters periods by DB max date, cyclic asset padding, cursor with crash recovery
4. **Benchmark after blocks (not every merge)** — 4 merges per block by default, avoids benchmark overhead
5. **`_use_gpu_synth` gated** — prevents GPU synth startup when historical mode active

### Debugging During Launch

- **Schedule JSON format mismatch**: Periods used timestamp integers (`start`/`end`) and `available_assets` key, not date strings. Fixed `HistoricalScheduleManager` to handle both formats.
- **Benchmark periods format**: JSON was `{"periods": [...]}` dict, not bare list. Fixed unwrapping.
- **Training/benchmark date overlap**: Timestamp vs date string comparison caused false positives. Changed from hard crash to warning + automatic removal of overlapping runs.
- **Encoder shape mismatch (64 vs 61 assets)**: 2018 period had 61 assets in DB. Added cyclic padding (`np.tile`) in `_refill_buffer()` after `get_window_random()`.
- **DSe dashboard**: Updated glob patterns for `branch_A_historical_*.csv` and `branch_B_bella_*.csv`. Fixed DataFrame `or` operator for None checks.

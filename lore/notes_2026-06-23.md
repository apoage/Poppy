## TASK_809 — CLOSED: ceiling-bound (the "+5.08 rescue" was an annualization artifact)

The 809 full run surfaced a passing cell — gated_maker H=1 k=16 long_short τ=0.75 N=60 fee=0+adv=5bp,
**post-cost Sharpe +5.08, CI[+2.77,+7.63]**. It did not survive scrutiny. The operator caught the flaw:
the +5.08 annualizes the **per-bar** net series by √525600, but the 60-bar min-hold makes per-bar
returns autocorrelated → the per-bar annualization over-counts independent periods. The honest number
aggregates to **per-rebalance/holding-period returns × √(rebalances/yr)** (operator estimate +0.66–1.5,
eroded further by adverse selection). Combined with the maker-fill model's known optimism, **809 is
ceiling-bound**: the LS+min-hold+maker corner is the quantified closest approach, not a working trader.
(The honest per-rebalance recompute — `recompute_best.py` — was written and is correct, but never ran:
host contention, below.) **Lesson banked: never annualize per-bar on a min-hold strategy — aggregate to
the holding period.** decide.py + GUARDS.md + result.md stand as the audited 809 artifacts.

## TASK_810 — the decisive fork: can a POST-COST-OBJECTIVE model beat linear on Kraken 1-min?

The open lever after 808/809 closed the *linear* signal: 806's encoder was **oracle-trained** (666 leaky
distillation — no trading gradient). **Nobody has trained a model whose gradient optimizes realized
post-cost P&L.** That's the one untested formulation that actually points at "a model that trades
profitably." 810 is the cheap small-model gate before the expensive full-encoder effort (TASK_811).

**The build (`runs/810_postcost_headroom/model.py`):** a small per-asset MLP (126→64→32→1; 63 lagged
1-min returns + 63 cross-sectional-context) + a differentiable market-neutral portfolio, trained on the
**post-cost trading objective**:
`loss = −mean_t[ Σ_a w_a·r_a − cost·Σ|Δw| ]` — the gradient flows through the portfolio AND the cost, a
real trading gradient forcing cost-aware, low-turnover, selective trading (the thing 666's MSE-to-oracle
loss never had). Leak-safe by construction: `w_a(t)=portfolio(MLP(features ≤ t))`, the realized return
is the LABEL (loss only, entry lagged to t+1, G8), never an input. Per-rebalance Sharpe (hourly
holding-period × √(525600/60)) — explicitly NOT the per-bar √525600 that bit 809. Apples-to-apples vs
the 806 linear (same portfolio + cost + Sharpe; differ only in scorer).

**Two smoke-caught design issues (the smoke earns its keep, every time):**
1. tiny portfolio exposure (tanh of small scores, unnormalized) → uninterpretable micro-bleed Sharpe
   (−200s for both arms). Fix: **fully-invested gross-1 market-neutral** (Σ|w|=1), interpretable +
   808-comparable; the model controls cost via the turnover penalty (stable rankings), not by shrinking.
2. the H=1 1-bar-hold regime is structurally hard (post-entry-lag mean-reversion); the model's potential
   edge is learning what linear can't (contrarian / stable-rank). The full run (3000 steps) is the test.

## The host-contention oomd saga → the VRAM-RESIDENT solution (the elegant part)

gpu-server turned out to be a **busy multi-tenant box**, not a dedicated ML host: **3 GitHub Actions
self-hosted runners** (CI builds that surge RAM), a **Docker web stack** (Next.js ×3, Kong, postgrest,
Erlang/beam), **ComfyUI 20.6 G**, bitcoind 8.4 G, VBoxHeadless 10.5 G — leaving only **~3 G free** with
~390 G in reclaimable page cache. systemd-oomd **pressure-kills any RAM-churning job** at that free level,
regardless of cgroup cap (the cap never helped — oomd kills on PSI, not the cap). This killed the 809
recompute (3×), the 810 numpy smokes, repeatedly. `ManagedOOMMemoryPressure=auto`, swap caps, chunked
peaks (3.3 G) — none survived the contention.

**The operator's move: "need to run on vram."** The GPUs are idle (24 G each); the RAM is the contended
resource. So the pipeline was rewritten **VRAM-resident**: `close` stays in RAM (505 MB, harmless) but
**every heavy op — the feature gather, the linear ridge (chunked normal equations), the model, the eval
— runs in JAX on the GPU**. Host RAM stays ~1.5 G *flat*, so oomd has nothing to reach for. The numpy
feature build (the oomd trigger) simply no longer exists on the host. Value-identity is asserted, not
assumed: the JAX feature gather is checked `|Δ|max < 1e-4` vs `probe.features_linear_xs`, and the JAX
ridge IC is checked `== 806` (0.1511 ± 2e-3). It's a satisfying shape — **the job hides and lives in
VRAM while the host thrashes around it**, and it's also just the correct architecture for a contended
shared server with free GPUs.

## RESULT (full run landed) — **HEADROOM FOUND (relative); flags TASK_811**

> ⚠️ **OVERTURNED 2026-06-25 — see `lore/notes_2026-06-25.md`.** The independent audit + a corrected
> measurement (H-strided rows + gross cost=0 Sharpe) proved this was a *turnover-reduction artifact*:
> the model beats linear on NET only by trading less; on GROSS it scores WORSE (model +15.43 vs linear
> +24.43 on OOS). Fork-C closed; NO TASK_811. The "headroom" below is the false positive the audit caught.

Two design fixes after the first smokes: (1) the H=1 1-bar-hold regime is the cost trap (market-neutral
1-bar book → ~zero gross variance, cost dominates, Sharpe magnitudes blow up scale-invariantly) → moved
the **hold to H=20** (audited 806/808 low-cost regime; features stay 1-min). (2) plain mean-PnL drove
val-Sharpe the WRONG way (model raised mean by taking turnover/variance) → switched to a **differentiable
post-cost SHARPE surrogate** `−mean(net)/std(net)` (spec-allowed), which aligned training with the gate
(val-Sharpe then climbed −266→−122 over 3000 steps, turnover fell).

**Full run (3000 steps, VRAM, ~4 min):** value-identity confirmed (features |Δ|=9.89e-07 vs probe; ridge
IC 0.05982 == 806's 0.0598). **On the strict-OOS test window the model robustly beats linear post-cost:
model annualized Sharpe −105.4 (CI [−108,−103]) vs linear −266.4 — CI-separated — at turnover 0.94 vs
1.36.** Beats linear in all 5 evaluable windows. **Mechanism: the model learned to trade selectively
(lower turnover) — the cost-aware "decide when to trade" the right objective was meant to induce, which
806's oracle-distilled encoder never had.** First time anything beats linear post-cost on clean OOS.

**Honest caveat — this is RELATIVE headroom, not a working trader.** Both are still negative everywhere;
model clears Sharpe≥1 in **0** windows (per-period model −0.65 vs linear −1.64 at the 20-min frequency).
The objective extracts more post-cost than linear; it does not reach profitability at small-model scale.
2022 regimes unusable (train-locked universe, 1 bar); 2023-24 regimes in-sample (flagged); verdict on
TEST_oos.

**Meaning:** the **post-cost trading objective is the right lever** — the one untested formulation, and it
works directionally where 666's oracle-imitation failed. This warrants **TASK_811** (full encoder on this
objective) as the credible path toward crossing into profitability. **STOPPED for the independent audit.**
Deliverables: `runs/810_postcost_headroom/` model.py + GUARDS.md + result.md. Audit crux: is the relative
win durable headroom or a turnover-reduction artifact that won't extrapolate?

## Lessons (Bloom-worthy)

1. **Annualize at the holding period, never per-bar.** The 809 "+5.08" was a √(holding/1-bar) inflation.
   A min-hold or persistent-position strategy MUST aggregate per-bar returns to the holding period before
   Sharpe — the block-bootstrap CI alone doesn't save you if the point estimate is per-bar.
2. **OOM-safety-by-construction extends to *where the memory lives*.** On a RAM-contended box with idle
   GPUs, the fix isn't a tighter cap (oomd kills on pressure, not cap) — it's to *not hold the memory on
   the host*. Keep the small base array in RAM, push every churning computation into VRAM, assert
   value-identity. The host can't kill what it isn't asked to hold.
3. **The right objective is the whole experiment.** 666 failed not for lack of a model but for the wrong
   gradient (imitate a leaky oracle). 810 changes one thing — the loss is realized post-cost P&L — and
   that single change is the only untested lever left for the operator's goal.

## Ceiling Research — Task Creation

Reviewed 4 independent analyses (GLM-4.7 ×2, Gemini ×1, Claude ×1). All converge on the same root cause: **encoder bottleneck** (1,728:1 compression, 1 dim per asset).

### Tasks Created

| Task | Name | Priority | Effort | Expected Impact |
|------|------|----------|--------|-----------------|
| TASK_683 | Widen Encoder + State (embed=64, state=128) | 1 | Medium | +9-14pp balanced |
| TASK_684 | Decouple hidden_dim from state_dim | 1 (prereq) | Low | Enables TASK_683 |
| TASK_685 | Gradient clip 1.0→5.0 | 2 | Trivial | Unblocks value head |
| TASK_686 | bfloat16 mixed precision | 3 | Low | -25% VRAM, enables wider model |
| TASK_687 | Hard example mining (trade_sample_prob 0.15→0.30) | 4 | Trivial | +5-9pp trade accuracy |

### Rejected Strategies

| Strategy | Why Rejected |
|----------|-------------|
| Focal loss | Fix gradient flow first (003). Focal + aggressive clipping = double suppression |
| Two-stage head | High effort. Current arch CAN learn (43% trade proves it). Fix representation first |
| Curriculum phasing | Low expected impact. Model already sees all L0-L14 |
| Real data mixing | Fix synthetic performance first (61%→75%), then tackle domain gap |
| Pure model scaling (more H/L) | Wrong axis. Adding reasoning on 64-dim state is wasteful. Widen state first |
| Oracle tuning (k=8) | Oracle ambiguity is NOT the bottleneck (97.1% ceiling confirmed) |

### Implementation Order

1. TASK_684 (decouple hidden_dim) — prerequisite
2. TASK_685 (grad clip) — can test independently on current run
3. TASK_686 (bfloat16) — needed to fit wider model
4. TASK_683 (widen encoder) — the main fix, fresh run required
5. TASK_687 (hard examples) — after architecture change settles

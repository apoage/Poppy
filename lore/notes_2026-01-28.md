### Bug Fixes

**1. Date Filter Not Applied (--periods-file)**
- **Issue**: When using `--periods-file` with `--jax-env`, dates weren't reaching the environment
- **Cause**: `train_jax_fast.py` JAX historical path used `config.start_date` directly, ignoring periods file
- **Fix**: Added periods file parsing in the JAX env path to extract first period's dates
- **Result**: Now shows `Date filter: 1539727200 to 1555279200` (correct period timestamps)

**2. JAX TracerBoolConversionError**
- **Issue**: `jax.errors.TracerBoolConversionError` in trainer.py line 1082
- **Cause**: Used `jnp.any(log_price_seq != 0)` (traced value) in Python `if` statement
- **Fix**: Removed runtime check, kept only compile-time `is not None` check
- **Note**: Can't use traced booleans in Python conditionals inside JIT

**3. System Crash / "Red Bars" (TASK_120) - RESOLVED**
- **Issue**: Desktop/terminal crashes after Epoch 1. `htop` showed high kernel time (red bars).
- **Diagnosis**: Memory Compaction Pressure. `run_self_play_jax` was eagerly allocating a ~10GB contiguous block for observations (15 envs * 1440 steps). Even with free RAM, the kernel struggled to find contiguous physical space, causing thrashing/crashes.
- **Solution**: Implemented **TASK_120: Lazy Observation Reconstruction**.
- **Implementation**: 
    - `run_self_play_jax` now returns `window_starts` metadata instead of full tensors.
    - `train_jax_fast.py` reconstructs observations one-by-one (600MB each) just before replay buffer insertion.
- **Result**: Reduced peak RAM spike from 10GB to <1GB. System stable.

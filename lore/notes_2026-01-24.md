## CRITICAL BUG FIX: Noise Schedule Exponential Decay

**Issue:** `--noise-schedule` caused price noise to exponentially DECAY instead of linearly RAMP.

**Symptom:** Training output showed `P:0%` while J/D/Φ ramped correctly:
```
Noise[P:0% J:5 D:30% Φ:50%]  ← P should be 100% at epoch 50!
```

**Root Cause (train_jax_fast.py:383):**
```python
# BUG: Overwrites target with current value
config.synthetic_noise = noise_cfg.price_noise  # = 0.02 at epoch 1

# Next epoch uses MODIFIED value:
price_noise = config.synthetic_noise * progress  # = 0.02 * 0.04 = 0.0008 ← WRONG!
```

**Fix:** Store original target noise before loop starts:
```python
if not hasattr(config, '_noise_target'):
    config._noise_target = config.synthetic_noise  # Store once

price_noise = config._noise_target * progress  # Always use original target
```

**Impact:** All L0-L14 noise ramp phases in dojo_v4 were training with near-zero price noise. The agent learned from jitter/dilation/phase but NOT from price perturbations.

**Recovery:** Need to re-run noise phases with fixed code.

## Dojo V4 System Summary

### Overview

Automated 3-phase curriculum that trains a fresh model from scratch to production-ready.

### Phase 1: Per-Level Training (L0-L14)

~1500 epochs total (100 per level × 15 levels)

For each level:
- **50 epochs basic** (0% noise) - learn clean pattern
- **50 epochs noise** (0%→100% ramp) - generalization

**Curriculum Levels:**

| Levels | Category | Examples |
|--------|----------|----------|
| 0-4 | Basic Mechanics | sine, lagged, dip, noisy_trends, rotation |
| 5-7 | Statistical Arbitrage | pairs, triangle_arb, index_arb |
| 8-10 | Momentum/Reversal | momentum, mean_reversion, breakout |
| 11-13 | Microstructure | bid_ask_bounce, order_imbalance, market_making |
| 14 | Volatility | GARCH(1,1) clustering |

**Auto-trigger:** Burning money enabled if hold rate > 60%

### Phase 2: Speed Training (300 epochs)

**Weighted random level selection** + **adaptive difficulty**

**Level Weights:**
- Easy (L0-L4): ~10% selection
- Medium (L5-L9): ~30% selection
- Hard (L10-L14): ~60% selection

**Adaptive Difficulty (triggers based on performance):**

| Feature | Trigger Condition | Effect |
|---------|-------------------|--------|
| **Adaptive Noise** | reward > 5 AND rising | Enables 4-stage noise: price → jitter → dilation → phase_shift |
| **Fees** | reward > 5 AND rising AND noise active | Ramps 0→28 bps (0.5 bps/epoch) |
| **Burning Money** | hold rate > 50% | Enables cash decay + **adaptive burn escalation** (5 stages) |

**Benchmarks:** Mandatory after Phase 2, retry up to 3x if avg reward < 5

### Phase 3: Historical Training

**Real market data** from `trading_data.db` (96 years)

- Calls `dojo_v3_historical.py --stratified`
- Cycles through time periods (prevents catastrophic forgetting)
- **Benchmarks every 60 epochs** (one block = H01, H02, H03, ...)
- **No timeout** - runs until data exhausted or failure

Added to `mcts_trader/training/cli.py` and `config.py`:
```bash

```

**Weights (hard levels get more training):**
- L0-L4 (easy): ~12%
- L5-L9 (medium): ~32%
- L10-L14 (hard): ~56%

### Pre-Generation at Startup

When `--weighted-synthetic` is used:
1. Pre-generates ALL 15 levels (L0-L14) at startup with progress bar
2. Stores in memory cache: `pregenerated_levels = {0: (states, prices, cfg), ...}`
3. During training: instant swap between levels from cache

### Async Background Regeneration

After using a level:
1. Old level is queued for async regeneration in background thread
2. `ThreadPoolExecutor(max_workers=1)` handles regeneration
3. Fresh data ready next time that level is selected

**Output during training:**
```

```

## Runtime Noise Application for JAX Env

**Issue:** Adaptive noise wasn't being applied when using `--weighted-synthetic` with pre-generated data.

**Root Cause:** Noise was only applied during data generation (`SyntheticMarket`), not at runtime. Pre-generated data had noise=0.

**Solution:** Added `apply_runtime_price_noise()` function that perturbs prices BEFORE self-play:

```python
def apply_runtime_price_noise(prices: jnp.ndarray, noise_level: float, rng_key: jnp.ndarray) -> jnp.ndarray:
    """Apply price noise perturbations to JAX price array at runtime."""
    if noise_level <= 0:
        return prices

    # Scale noise to be proportional to price volatility
    log_returns = jnp.diff(jnp.log(prices + 1e-10), axis=0)
    volatility = jnp.std(log_returns, axis=0, keepdims=True)

    # Generate multiplicative noise
    noise = jax.random.normal(rng_key, shape=prices.shape)
    noise_scale = noise_level * volatility * 10.0

    # Apply multiplicative noise
    perturbed = prices * (1.0 + noise_scale * noise)
    return jnp.maximum(perturbed, 0.01)
```

**Integration (train_jax_fast.py:571-580):**
```python
if jax_env_states is not None:
    # Apply price noise at runtime if adaptive noise is active
    prices_for_play = jax_prices
    if hasattr(config, '_noise_config') and config._noise_config.price_noise > 0:
        noise_rng, search_rng = jax.random.split(search_rng)
        prices_for_play = apply_runtime_price_noise(
            jax_prices, config._noise_config.price_noise, noise_rng
        )
```

**Note:** Temporal jitter, time dilation, and phase shift require generation-time application - now properly passed through async regeneration (see fix below).

## Huber Loss for Prediction Head

**Issue:** Prediction loss spiking to 100+ on certain levels (e.g., L6 triangle_arb), destabilizing training:

```
Epoch 24 (L12): Pred: 0.54  | StepK: 0.09   ← normal
Epoch 25 (L8):  Pred: 19.4  | StepK: 3.63   ← elevated
Epoch 26 (L6):  Pred: 101.8 | StepK: 77.96  ← EXPLODED!
Epoch 27 (L11): Pred: 0.64  | StepK: 0.01   ← back to normal
```

**Root Cause:** MSE loss has unbounded gradients for large errors. Hard-to-predict levels like L6 (statistical arbitrage with complex correlations) cause massive gradient spikes.

**Solution:** Huber loss - quadratic for small errors, linear for large:
- When `|error| ≤ delta`: Loss = 0.5 * error²  (like MSE)
- When `|error| > delta`: Loss = delta * (|error| - 0.5 * delta)  (capped gradient)

**New CLI flags:**
```bash
--pred-loss-type huber    # Use Huber instead of MSE (default: mse)
--pred-huber-delta 1.0    # Delta threshold (default: 1.0)
```

**Checkpoint compatibility:** ✅ No architecture changes - loads existing checkpoints fine.

2. Escalates to higher stage (base, market, random, aggressive, hardcore)
3. JAX env config updated via `.replace()` with new burn rate
4. Each step: cash holders get reward penalty ∝ cash_ratio × (market_return + base_rate)

## Random Burns (Wife with Debit Card Mode)

**Request:** Add random chance to burn 0-500 in one step, up to 10 times per epoch. Extra pressure beyond base burn.

**Implementation:** Extended burning money in JAX env with random burns:

### New Config Fields (EnvConfig)

```python

burn_random_prob: float = 0.02      # 2% chance per step
burn_random_max: float = 500.0      # Max random burn amount ($)
burn_random_limit: int = 10         # Max burns per episode
```

### New State Field (TradingState)

```python
random_burns_remaining: chex.Array  # Tracks burns left this episode
```

### Random Burn Logic (step function)

```python
# Split RNG for random burn decisions
rng_key, burn_key1, burn_key2 = jax.random.split(new_state.rng_key, 3)
new_state = new_state.replace(rng_key=rng_key)

if config.burn_random:
    # Roll for burn
    roll = jax.random.uniform(burn_key1, ())
    burn_amount = jax.random.uniform(burn_key2, (), minval=0.0, maxval=config.burn_random_max)

    # Burn if: probability check AND burns remaining AND has cash
    should_burn = (roll < config.burn_random_prob) & (new_state.random_burns_remaining > 0)
    actual_burn = jnp.where(should_burn, jnp.minimum(burn_amount, new_state.cash), 0.0)

    # Deduct from cash
    new_cash = new_state.cash - actual_burn
    new_state = new_state.replace(cash=new_cash)

    # Decrement counter
    new_burns_remaining = jnp.where(should_burn, new_state.random_burns_remaining - 1, new_state.random_burns_remaining)
    new_state = new_state.replace(random_burns_remaining=new_burns_remaining)

    # Penalty to reward (proportional to portfolio)
    burn_pct = actual_burn / portfolio_value * 100.0
    reward = reward - symlog(burn_pct)
```

## TASK_110: Cycle Balance Implementation

**Problem:** H0 (first TRM cycle) showing 7x higher delta norms than H1-H3, indicating first-cycle dominance.

### Two Mechanisms Implemented

**1. Cycle Balance Loss** - Penalizes imbalanced utilization

```python
# Coefficient of variation (CV) of delta norms across H-cycles
# Target CV = 0.3 (allow 30% imbalance, penalize beyond)
loss = max(0, CV - target_cv)
```

**2. Cycle ATC** - Contrastive loss forcing H0/H3 diversity

```python
# Push H0 and H3 latents apart (opposite of standard contrastive)
# Forces later cycles to learn complementary features
loss = softplus(cosine_similarity(H0, H3) / temperature)
```

### CLI Flags

```bash

--cycle-balance-weight 0.1         # Loss weight
--cycle-balance-target-cv 0.3      # Target CV (0.3 = 30% allowed)

--cycle-atc-weight 0.05            # Loss weight
--cycle-atc-temperature 0.1        # Temperature (lower = stronger push)
```

### Root Cause: Absolute Log-Price Scale Mismatch

The prediction loss was computing MSE on **absolute log-prices**, not returns:

| Data Source | Price Range | Log-Price |
|-------------|-------------|-----------|
| Synthetic | ~100 | **~4.6** |
| Historical BTC | ~30,000-100,000 | **~10.3-11.5** |
| Historical ETH | ~1,500-5,000 | **~7.3-8.5** |

The prediction head was trained on synthetic log-prices (~4.6), but historical log-prices are 7-11.

**MSE calculation**: (10.3 - 4.6)² ≈ 32 per element × 64 assets × 5 steps = **360+ loss**

This is NOT because markets are unpredictable - it's a pure scale mismatch bug!

### Fix Applied (Two Iterations)

**First attempt (WRONG)**: Baseline subtraction
```python
# WRONG - pred_sequence is at decoder scale (~4.6), baseline is historical (~10.3)
baseline = teacher_sequence[:, :1, :]
pred_returns = pred_sequence - baseline  # 4.6 - 10.3 = -5.7 (STILL WRONG!)
```

**Second attempt (CORRECT)**: Step-to-step returns

**File**: `mcts_trader/jax_agent/trainer.py:677-697`

```python
# TASK_110 FIX: Use STEP-TO-STEP RETURNS (scale-invariant)
# Both pred and target step changes are ~0.001-0.01 regardless of absolute scale
teacher_initial = teacher_sequence[:, 0:1, :]

# Predicted returns: change from previous step
pred_step0 = pred_sequence[:, 0:1, :] - teacher_initial  # First pred vs teacher initial
pred_step_changes = pred_sequence[:, 1:, :] - pred_sequence[:, :-1, :]  # Subsequent steps
pred_returns = jnp.concatenate([pred_step0, pred_step_changes], axis=1)

# Target returns: change from previous step
target_step0 = target_sequence[:, 0:1, :] - teacher_initial
target_step_changes = target_sequence[:, 1:, :] - target_sequence[:, :-1, :]
target_returns = jnp.concatenate([target_step0, target_step_changes], axis=1)

# Loss on step-to-step changes (scale-invariant)
step_loss = jnp.mean((pred_returns - target_returns) ** 2, axis=-1)
```

### Actual Results After Fix

| Epoch | Prediction Loss | Notes |
|-------|-----------------|-------|
| Before fix | 360-400 | Stuck, not learning |
| Epoch 1 | 218 | Learning! |
| Epoch 2 | 255 | Period switch |
| Epoch 3 | 158 | Dropping |
| Epoch 4 | 147 | Still improving |

**Key insight**: Step-to-step changes are scale-invariant because:
- Synthetic: pred[t+1] - pred[t] ≈ 0.001-0.01
- Historical: target[t+1] - target[t] ≈ 0.001-0.01
- Even if absolute scales differ (4.6 vs 10.3), the *changes* are comparable

### Why This Matters

1. **Physics prediction CAN work on real markets** - the design is correct
2. The loss was artificially inflated by comparing prices at different absolute scales
3. Now prediction loss reflects actual prediction quality, not scale mismatch
4. Physics parameters (α, β, σ, Γ) can now train properly
5. Model is actively learning on historical data (loss dropping each epoch)

### Architecture

```
                         EXTERNAL CURRICULUM LOOP

   curriculum_bridge.py          generated_data/         train_jax_fast.py
   (Teacher process)             adversarial/            (Student process)
          │                           │                        │
          │  generate_and_save()      │                        │
          ├──────────────────────────▶│                        │
          │                           │ .npz files             │
          │                           │                        │
          │                           │ --adversarial-data-dir │
          │                           └───────────────────────▶│
          │                                                    │
          │                                                    │ load_adversarial_prices()
          │                                                    │ mix_adversarial_prices()
```

**Step 1: Generate adversarial data**
```bash
python -m diff_teacher.curriculum_bridge \

```

**Step 2: Train with mixed data**
```bash
python train_jax_fast.py \
```

### Why External Loop?

1. **Minimal trainer changes** - Only data loading, no training loop modification

## Session 3 — Multi-Model Review Results

### Regression Bug Hunt (3 reviewers: `prompt-lib/out-bha-{01,02,03}/`)

**FINDING-1 (CONFIRMED ×3): hidden_dim silently halved (2048 → 1024)**

Commit 06c44ab started passing `trm_hidden_dim` from config. `get_large_config()` sets 1024, but old implicit default was `state_dim * 16 = 2048`. Model dropped from ~48M to ~25.76M params. Trade discrimination (3.9% of decisions) needs that FFN capacity; hold prediction doesn't.

**FINDING-2 (CONFIRMED ×2): Model-state rollout target mismatch (DAgger error)**

Student state channels show model's position, but targets computed from oracle's position context. When student is Short and oracle is Long, target says "Hold" instead of "Buy." Contradictory gradients → collapse to majority class.

**FINDING-3 (LIKELY ×2): Bootstrap tax**

Model-state rollout replaced clean oracle state channels with noisy model-generated ones. Harder learning problem + less capacity = turtle.

**Ruled out by all 3**: BUG-1 returns alignment, BUG-2 confidence, BUG-7 sampling, LATENT fix, optimizer warmup guard.

### Action Taken

## Session 7 — DAgger Fix + AR Warmup + Trade Sampling

### Trade Sampling Dilution Fix

`trade_sample_prob=0.30` was per-episode-visit (single coin flip for ~9-20 contiguous samples). Changed to per-sample: each sample independently rolls the coin. Now exactly 30% of samples land on trade-heavy timesteps.

### DAgger Target Fix (FINDING-2)

When `autoregressive_state=True`, policy targets are now re-computed from the **student's** position (from model-state rollout) instead of the oracle's position. Applied to both single-episode and batch generation paths.

Logic: `optimal_path_to_policy(oracle_selections, returns, prev_selections=student_pos)` — "given where YOU are, what action gets you to where the oracle wants?"

### AR Warmup Schedule

New config field `ar_warmup_epochs=100`:
- **E0-99**: Oracle state channels (fast initial learning, but leaks oracle position)
- **E100+**: AR with DAgger targets (train→inference aligned, no leak)
- Log message at transition: `► AR warmup complete — switching to model-state rollout with DAgger targets`

Training flow:
1. First 100 epochs: model learns basic patterns from oracle-quality state channels
2. Epoch 100: generator receives model params, starts AR rollout
3. E100+: state channels come from model's own actions, targets from student-position-aware DAgger

## Ideas

### Oracle-as-MCTS Distillation (TASK_697, ON HOLD)

Oracle multipass already generates N rollouts with noise — natural mapping to MCTS simulations. Train TRM on MCTS-shaped targets (visit distributions, root values, per-step dynamics) instead of flat one-hot labels. Three phases: (A) oracle-as-fake-MCTS trains full MuZero including dynamics, (B) freeze TRM and bootstrap real MCTS, (C) gradual unfreeze → standard ExIt. Key win: also trains dynamics model (recurrent_inference) which Foxglove never touches, eliminating the Foxglove→Poppy representation gap. Needs new `bridge_trainer.py`, ~2 weeks, only after baseline recovered. Spec: `tasks/TASK_697_ORACLE_AS_MCTS_DISTILLATION.md`

# Lore — 2026-06-03

## §176 — The language gets built: `tools/candle_lang/`, and what the first words sound like

Yesterday the market got a *design* for a language. Today it got the language itself — or at least the
apparatus that mints one. `tools/candle_lang/` exists now: 15 modules, ~3.5k lines, built CPU-first on
the workstation, leak-audited for the server, and run end-to-end far enough to hear the first words come
out. The verdict on the build is clean. The verdict on the *language* is, honestly, not in yet — and
that gap is the whole point of how the eval was designed, so it's worth sitting with.

### How it was built — keystones by hand, the rest under a verify gate

The three load-bearing pieces I wrote and proved myself, because they're the ones that, if subtly wrong,
poison everything downstream silently:

- **`fsq_core.py`** — the salvaged C0 FSQ had a real bug: its `bound()` computed an even-level offset
  then threw it away, so for the default `(8,8,8,5,5)` codebook only 7 of every 8 levels per even dim
  were reachable and code 0 never fired. I replaced it with the reference FSQ (Mentzer et al.) — pre-tanh
  half-level shift — and, more importantly, wrote a *reachability gate* that's now a hard assertion at
  `train_l4` startup: sweep the levels, confirm every dim reaches all L codes and the mixed-radix basis
  is a bijection onto `[0, prod)`. My first version of the gate was itself wrong — it tested random-id
  coverage and failed on a coupon-collector artifact (20k Gaussian draws can't cover 12,800 codes). The
  fix was to test the two things that *actually* imply reachability (per-dim coverage + basis bijection),
  not a saturation proxy. A small lesson re-learned: a test that fails for the wrong reason is worse than
  no test. Now it passes for even, odd, and mixed level configs.

- **`volunit.py`** — the vol-unit substrate, the per-bar feature kernel every panel member shares.
  Causal EWMA σ (re-anchored each UTC-day so the 24/7 corpus doesn't drift), `mv/gap/body/range` in
  vol-units, wick fractions raw. The property that the whole "transfer-by-construction" bet rests on is
  rescale-invariance, and it now holds *byte-identically*: rescale the price by λ anywhere from 0.001 to
  7777 and `max|Δfeature| = 0.000e+00`, exact zero. A token on a $0.007 coin and a $105k coin are the
  same token because the features literally are the same bits. That's not a tolerance — it's an identity.

- **`config.py`** — the binding interface contract (the 6-channel substrate, the batch shape, the corpus
  split). I wrote it first and froze it so the fan-out had a fixed thing to build against.

The other 13 — the streaming DB reader, the base alphabet, the conv-VQ L4 model, the leak-proof GPU
harness, the five-member eval battery, the four symbolic languages (BPE / ABBA / SAX-grammar /
Matrix-Profile), and the tmux orchestrator — were built by a single verify-gated workflow (`wl3uffw6j`,
22 agents, 1.4M tokens) against that pinned contract. Library tier → barrier → entry tier → an
adversarial audit keyed to the six leak/OOM corrections from yesterday's audit → a CPU smoke. The audit
came back the way you want one to: **all six blocking corrections SATISFIED with file:line evidence** —
no blind `--gpu 1,2,3` (the orchestrator gates on `nvidia-smi` idleness; single-GPU is the default), the
FSQ gate is wired in before the device ever initializes, the eval reductions are online `bincount`
accumulators (no full token-stream ever lands on the host), the tail batch is padded and loss-masked so
the jit never retraces, the train step donates only the batch buffer and never the params. The only
confirmed finding across the whole audit was a *stale docstring* on an A2 helper — the computation was
correct, the comment lied — which I fixed. Everything else the crossval demoted as latent doc-smell. The
streaming reader earned its keep on its own synthetic test: a planted 10-minute gap and a NULL-close bar
both correctly broke the `dt==60` run, nothing forward-filled, cross-page runs stitched without loss.

### What the first words sound like — and why the gates are *supposed* to be unhappy

The smoke ran `l1_bpe` — the primary language, BPE over numerosity-reduced base symbols — end-to-end
under `safe_run --cpu` on three build assets and one held-out coin, ~2000 windows each, in 284 seconds.
It streamed the real 25 GB database (1193 assets, not the 64 I'd assumed — the trading universe is
Poppy's, the *corpus* is everything). It produced the full non-predictive scorecard. And the scorecard
says:

- **A0 (rescale invariance): 1.0000**, 48 trials, λ ∈ {0.01, 100}. The substrate's byte-identity
  survives all the way through BPE tokenization — the same window at two wildly different price scales
  produces the *same token id*. The one gate that's a correctness pre-condition rather than a quality
  judgment: passed, exactly.
- **A1 (MDL compression): 0.43** — the language is currently *more expensive* than coding each bar
  independently. Look closer and the reason is honest: boundary bits (1.53M) roughly equal the covered
  bits (1.25M). We're charging ourselves for every token boundary, as the design insisted we must, and at
  410 merges there aren't enough long words yet to amortize that cost.
- **A2 (reconstruction): 7% of bars within tolerance**, mean log-ratio MSE ~5. An 8-bin move alphabet
  cumulated over 32 bars drifts badly. Coarse vocabulary, coarse reconstruction.
- **A8 (cross-asset transfer): does NOT beat the control.** Holdout coverage 0.993 against a phase-shuffle
  control's 0.9995 — the *control* is higher. This is the headline gate, the one that's supposed to
  decide whether the whole branch lives, and at three build assets it is telling us nothing yet except
  that three assets isn't a corpus.
- **A9 (length non-degeneracy): pass.** The words aren't all length-1; the distribution isn't collapsed.

Here's the thing I want to record plainly, because it's easy to read that scorecard as "four of five
gates failed, kill it." That reading is wrong, and the reason it's wrong is *why we built this eval the
way we did*. These are smoke numbers: three assets, two thousand windows, four hundred merges. A1, A2,
and A8 are all quantities that should improve with corpus size and vocabulary depth — more assets to
share merges across, more merges to amortize boundaries, a finer alphabet to reconstruct with. The smoke
proved the *machine* works: it streams, it tokenizes, it scores, it doesn't leak, and the one property
that had to be exact *is* exact. Whether the language is any *good* — whether a vocabulary fit on
Bitcoin-scale assets genuinely transfers to a sub-cent coin better than chance, with mega-tokens
excluded, beating both a returns-shuffle and a random-merge vocab — that is a full-corpus question, and
it is the next experiment, not this one. We have, for the first time on this branch, an instrument that
can answer it honestly. Yesterday's loss-side nulls (A +0.35, A2 +0.06) told us the representation had
to change. This is the apparatus that finds out whether a *language* is the change that matters. The
machine is built and trustworthy. The verdict is still out, and it's supposed to be.

## §204 — The B3 universe resolution: the missing-key trap (TASK_740 class) and proving the full reachable set

**What was believed before.** The handoff (UNCERTAIN block) flagged the foxglove arm asset universe as
*not settled*: resolve it from "the benchmark's symbol_to_id vs the DB asset table vs per-period union
— NOT settled this session." And it carried a wrong working number: "59–64/period."

**Why the universe MUST be exact — the trap.** `shift_fe` is a cyclic-shift null: the hot path
(`tools/candle_lang/token_hotpath.py:225`, `_get_shifted_timeline`) looks up each asset's roll offset
as `sn["offsets"].get(int(asset_id), 0)`. The `.get(…, 0)` default is the landmine — **an asset
MISSING from the spec gets offset 0 = no roll = the real timeline served verbatim.** A null arm
silently contaminated with real token↔bar alignment is exactly the TASK_740 failure class (silent
key-mismatch poisons a control). So the spec must cover the *full reachable universe* — every asset the
trainer can ever tokenize across the run — or the null is quietly not a null.

**What happened (the resolution).** `config/foxglove_periods.json` has **270 periods**, not "59–64" —
that number was the *per-period asset count* (range 2–64), never the universe. `SegmentPool.advance_period`
round-robins all 270 periods over the run, so every period's assets are reachable; the universe is the
**union** across all 270 periods, not any single period.

- Union of `assets` over all 270 periods = **835 symbols**.
- `min_assets=32` filters out periods smaller than 32 assets. Exactly **one** period has fewer (a
  2-asset period), and its members are **CHEEMSUSD + COQUSD** (two meme-coins reachable nowhere else).
  Excluding that period drops those 2 → **833 symbols** in the served universe.
- All 833 resolved cleanly to DB ids via the **exact HistoricalMarket query path**
  (`SELECT id, symbol FROM assets WHERE symbol IN (…)`), so the spec's integer keys are byte-for-byte
  the same ids the trainer's `tokenize_grid` looks up. No remapping layer, no order dependence — the
  thing that silently broke TASK_740 cannot recur here because the spec keys and the tokenize keys come
  out of the same SELECT.

**The reversal.** The handoff's "59–64/period → DB ids" universe was wrong twice over: wrong *scope*
(per-period, not union) and wrong *number* (count, not symbols). Corrected to **270 periods → 835 union
→ 833 after `min_assets=32`**. The spec is now built over the full 833-asset reachable set, so every
asset the trainer can tokenize carries a real roll offset and no asset falls through to the contaminating
`.get(…, 0)` default.

**Lesson.** When a control's correctness rests on a dict `.get(key, default)`, the proof obligation is
not "does the spec have keys" but "is the key set the *complete reachable* set" — and the reachable set
is whatever the period scheduler can round-robin to, not whatever one slot shows.

## §206 — Bonus discovery: the disk token-cache self-builds — no standalone prebuild script needed

**What was believed before.** Handoff UNCERTAIN: "Whether the real disk artifact has a standalone
prebuild trigger — `build_shift_null` has no `--cache-dir`; no standalone entry found; a small prebuild
script may be needed in the launch pass." I.e. an open worry that B3 would need new glue code to warm
the shared token cache before the runs.

**What happened.** Reading `tools/candle_lang/token_hotpath.py` closed it: the disk artifact
**self-builds on first run**, no prebuild trigger required.

- `write_disk_artifact` (`token_hotpath.py:345`) does `os.makedirs(str(cache_dir), exist_ok=True)`
  before `np.savez` — it creates its own cache directory, so an absent cache dir is not an error.
- `load_disk_artifact` (`token_hotpath.py:322`) returns **0** on a missing artifact
  (`if not os.path.isfile(path): return 0`) — a cold cache is a clean miss, not a crash. The pool then
  annotates normally and writes the artifact after the first pass.

So the first run cold-annotates and warms the artifact; the subsequent 8 runs load it once to RAM and
skip re-annotation (the ~30h-saved load-once-to-RAM pattern). No prebuild script. **The "no standalone
prebuild trigger" uncertainty was moot — the absence of a trigger is the design, not a gap.**

**Lesson.** An "UNCERTAIN: maybe we need to build X" is sometimes resolved not by building X but by
reading the code that proves X was never needed. Cheaper than the script that would have been wrong.

## §207 — The 20-hour autonomous queue: saturate the one bottleneck, fill the rest with reversible work

**Context.** User away ~20h; standing priority is "gpu-server must never idle"
(`feedback_server_stays_under_load`). The 804 campaign is itself ~a 20h job (B3 ~2–3h CPU → 9 runs
2-wide ~15–18 GPU-h). The GPU is fully consumed by it (TASK_742 caps concurrency), so every *additional*
lane must be CPU- or agent-only — the GPU axis is already maxed.

**The decision (user-authorized).** Auto-launch is **gated on the two-sha exit check**: the real
`vocab_sha` (cb-1376 base) and the derived `shift_fe` sha must be **distinct and deterministic**. If
they pass → auto-launch the orchestrator. If they fail → **hold + report**, do not launch. On top of the
gated GPU campaign, four parallel reversible lanes:

1. **TASK_802** — dynamics-head build (the follow-on candle-language structural piece). Code-write, no
   GPU.
2. **QA pre-flight** — read-only audit of the campaign code before the 18 GPU-h commit (the cheap check
   in front of the expensive run, §203).
3. **This lore** — the session-continuity + Bloom artifact (the lane you're reading).
4. **Follow-on queue** — staged next work so an early campaign finish doesn't idle the box.

**Bloom theme to draw out later.** This is the §203 discipline scaled to a whole unattended window: the
*one* irreversible, bottlenecked resource (GPU) gets a hard exit-check gate; everything else is
reversible (code you can revert, audits that touch nothing, notes) and runs free in parallel. You don't
need a human in the loop for reversible work — you need one only at the irreversible boundary, and there
you replace the human with a cheap deterministic check (two shas) that holds on failure.

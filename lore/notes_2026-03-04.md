## Session 24 — TASK_702: e-dojo Historical Training (Proper Implementation)

### What Was Done

Implemented proper historical training mode for e-dojo, porting features from dojo_v3
(which targets Poppy/train_jax_fast.py) to Foxglove's dual-branch merge architecture.

### Implementation (6 phases, all in `tools/orchestration/e-dojo_v1.py`)

| Phase | What |
|-------|------|
| A | `HistoricalScheduleManager` class — loads schedule JSON, filters periods by DB max date, flattens into runs, manages cursor/block progression |
| B | Extended `DojoState` with `historical_block_count`, `runs_since_last_block`, `historical_mode`; wired schedule manager into `check_and_merge()` |
| C | Replaced inline schedule reading in `restart_both_with_checkpoint()` and `launch_dual_branches()` with `schedule_manager.get_current_run()` calls; cleaned up `_historical_args` |
| D | Added `_handle_block_completion()` — copies merged checkpoint to `foxglove_H{N}.pkl`; `_run_block_benchmark()` — shells out to `benchmark_easy.py --json --quiet` |
| E | CLI flags: `--runs-per-block`, `--loop`, `--max-blocks`, `--start-block`; wired into `main()` and `run_loop()` |
| F | Validation: `py_compile` passes, AST parse confirms all 5 classes present, `--help` shows all new flags |

### Key Design Decisions

- **Period advancement happens in merge cycle**: `schedule_manager.advance()` called after merge, before branch restart — so `restart_both_with_checkpoint()` picks up new period bounds
- **Block = N runs**: Every `runs_per_block` (default 4) merges → save named checkpoint + run benchmark
- **Benchmark runs AFTER branch restart**: So training continues while benchmark evaluates the block checkpoint
- **Loop mode**: `--loop` cycles forever; `--max-blocks` provides a stop condition
- **State persistence**: cursor, block_count, runs_since_last_block all saved in `dojo_state.json` for crash recovery

### What Changed vs TASK_698

TASK_698 added basic `--branch-a-historical` support (one period per merge, no blocks, no benchmarks).
TASK_702 replaces that with:
- Run-level granularity (not just period-level)
- Block checkpoints (foxglove_H01.pkl, H02, ...)
- Benchmark integration between blocks
- Loop/one-shot mode control
- Schedule validation (DB max date filtering)
- Clean schedule manager abstraction (removed inline JSON parsing)

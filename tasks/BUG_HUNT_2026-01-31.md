## BUG_A: Post-Done Reward Accumulation (CONFIRMED)

### Symptom
Epoch 27 batch7: `reward=-30.99` (normal: ~-2)

### Root Cause
**File**: `mcts_trader/training/self_play.py:722`

```python
# BUG: Sums ALL rewards including post-termination steps!
scores = np.sum(cpu_rewards, axis=1)  # <-- WRONG

# But training data is correctly sliced:
rewards_arr = cpu_rewards[i, :n_steps_i]  # <-- CORRECT
```

### Analysis
1. JAX scan runs for fixed `steps` (1440) regardless of `done` flag
2. After liquidation (`done=True`), environment keeps stepping
3. Each post-done step generates `symlog(-50) = -3.93` reward
4. These post-done rewards are included in `scores` but NOT in training data
5. Result: Logged metric corrupted, training unaffected

### Math Verification
- Normal reward: ~-2 (sum of ~1440 small symlog values)
- With 8 post-done steps: -2 + (8 × -3.93) = -33.4 ≈ -30.99 ✓

### Fix
```python
# Option 1: Mask rewards before summing
masked_rewards = cpu_rewards * (1 - np.cumsum(cpu_dones, axis=1).clip(0, 1))
masked_rewards[:, 0] = cpu_rewards[:, 0]  # Keep first done step
scores = np.sum(masked_rewards, axis=1)

# Option 2: Per-env correct summing (simpler)
scores = []
for i in range(n_envs):
    if np.any(cpu_dones[i]):
        n_valid = int(np.argmax(cpu_dones[i]) + 1)
    else:
        n_valid = steps
    scores.append(np.sum(cpu_rewards[i, :n_valid]))
scores = np.array(scores)
```

## BUG_B: Unused `signs` Variable (MINOR)

### Symptom
Code computes `signs` but never uses it.

### Location
**File**: `mcts_trader/jax_agent/path_solver.py:95-96`

```python
# Compute actual PnL for this step (sign-aware)
# For simplicity, assume we go long on positive returns, short on negative
step_returns = returns[t]
signs = jnp.sign(step_returns)  # COMPUTED
step_pnl = jnp.sum(jnp.abs(step_returns) * new_mask)  # signs NOT USED
```

### Analysis
**NOT A BUG** - The logic is actually correct:
- Oracle picks top-k assets by |return|
- Long if return > 0, short if return < 0
- Profit = |return| in both cases (captured by abs)
- The `signs` variable is dead code, but PnL is correct

### Fix
Remove dead code:
```python
step_returns = returns[t]
# signs = jnp.sign(step_returns)  # DELETE: unused
step_pnl = jnp.sum(jnp.abs(step_returns) * new_mask)
```

## BUG_C: Metrics Data Source Mismatch (CONFIRMED)

### Symptom
`market_return > optimal_alpha` (epoch 13: 8.61 > 3.22) - mathematically impossible for oracle

### Root Cause
**The two metrics are computed on DIFFERENT data!**

| Metric | Source | Timing |
|--------|--------|--------|
| `market_return` | Current epoch's episode prices | Real-time |
| `optimal_alpha` | Batch sampled from replay buffer | Old data |

### Code Trace

**market_return** (`self_play.py:787`):
```python
# From CURRENT episode
asset_returns = (end_prices - start_prices) / (start_prices + 1e-8)
market_return = float(np.mean(asset_returns)) * 100
```

**optimal_alpha** (`trainer.py:1207-1226`):
```python
# From REPLAY BUFFER batch (could be from epochs ago!)
log_price_seq = batch.get('log_price_sequence')
returns_for_amax = log_price_seq[:, 1:, :] - log_price_seq[:, :-1, :]
optimal_path = compute_optimal_path(returns_for_amax[0], ...)
optimal_alpha_scaled = optimal_path.total_alpha * 100.0
```

### Impact
- Metrics comparison is meaningless
- Cannot validate oracle performance
- Imprinting (TASK_125) may learn from wrong targets

### Fix Options

**Option A: Compute optimal_alpha on current episode (RECOMMENDED)**
```python
# In self_play.py, compute optimal path on episode prices
from mcts_trader.jax_agent.path_solver import compute_optimal_path

log_returns = np.log(prices[1:] / prices[:-1])
optimal_path = compute_optimal_path(log_returns, k=4, method='greedy')
trajectory['optimal_alpha'] = optimal_path.total_alpha * 100.0
```

**Option B: Label metrics correctly**
```python
# Rename in CSV output
'batch_optimal_alpha': optimal_alpha_scaled,  # Clearly from batch
'episode_market_return': market_return,       # Clearly from episode
```

### Secondary Issue: Return Type Mismatch
- market_return: Linear returns ((P1-P0)/P0)
- optimal_alpha: Log returns (ln(P1/P0))

For 10% move: Linear=10%, Log=9.53%. Small but adds noise.
